## 계약과 선행 산출물

CW-05의 분리된 lifetime contract와 CW-06/08/11/12/13/14의 통합 결과를 소비한다. 사용자 입력 owner·취소·일시정지를 복구가 해제하지 않는다. Backend crash 뒤 child 생존·PTY 재연결을 확인 없이 주장하지 않는다. 재접속/복구는 일시정지를 해제하거나 중단 명령·대기 요청을 replay하지 않는다. C-D52 인수 요청/확인·전송된 명령 상태와 C-D51 control mode를 실제 프로세스와 대조하며, 이전 owner epoch/session의 요청을 replay하지 않는다.

선행 산출물·통합 경계는 PLAN의 이 ticket 및 `dependency_artifacts`를 따른다.

- CW-06: 세 영역 UI와 원본 OMP 직접 입력이 통합·검증됨.
- CW-08: OMP session ID와 불명 mailbox 처리 경계가 통합·검증됨.
- CW-11: 자동화 활성 중 detach 뒤 유지할 60초 점검과 일시정지 중 보류가 통합·검증됨.
- CW-12: 수명 전환 중 보존할 일시정지·취소 상태가 통합·검증됨.
- CW-13: 종료 확인과 manager 판단 경로가 통합·검증됨.
- CW-14: 영속 기록과 저장 장애 처리가 통합·검증됨.

계획 write scope: `src/workbench/runtime/**`, `src/workbench/app/**`, `tests/lifecycle/**`. 실제 dispatch 전에 Root가 current base·mutation lease·resource claim을 재확인한다.

## 검증

Detach 후 세 process와 사용자 owner 유지, 자동화 활성 중 주기 점검 지속·일시정지 중 새 모델 점검 보류, 재접속 중복 run 없음, agent/backend crash의 살아 있는/사라진 process 대조를 확인한다. OMP auth/API 오류 중 마지막 모델 확인 시각과 실행·관측 지속, 복구 후 재확인, 재부팅 후 사용자 확인 전 새 run 금지, 전체 종료 전 사용자 확인과 미종료 표시를 검증한다. 독립 test_designer/reviewer가 replay·중복 시작을 검토한다. 추가로 C-D52 인수 요청/확인·전달된 command 상태 및 C-D51 control mode를 detach/reconnect 뒤 대조한다. OMP process 교체에서 durable unknown/no replay를 검증하며 PID 존재만으로 identity를 확인했다고 간주하지 않는다. 실제 reboot 검증은 준비된 격리 환경에서만 수행하고 확보되지 않으면 pending으로 남긴다.

## 범위 밖과 중단 조건

실행·message 전달 여부를 알 수 없는 상태에서 자동 replay하거나 사용자 전체 종료/취소를 실패 복구로 되돌리면 중단한다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 동작 확대는 범위 밖이다. Gate item은 이 ticket 또는 전이적 선행 산출물만 사용한다. 후속 통합의 책임을 초기 통과 조건으로 요구하지 않는다.
