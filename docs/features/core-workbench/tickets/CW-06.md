## 제공할 동작

원본 manager OMP·worker OMP와 실제 host terminal을 한 화면에 표시하고 사용자 direct chat, focus, host 입력 owner, 상태·마지막 확인 시각을 분리해 보여준다. 제품 UI는 세 PTY를 직접 소유하지 않고 CW-17 backend에 `ui_v1`로 attach하는 client다. UI 종료는 detach이며 backend와 세 PTY를 종료하지 않는다. 기존 `ui/terminal_g1`의 VT 렌더링·input routing은 재사용할 수 있으나 `PtySession` 직접 소유와 종료 시 killpg는 제품 경로에서 사용하지 않는다.

## 수락 기준

- C-AC-01: 원본 manager OMP pane에서 목표·코드 대화. `P-C-AC-01`와 최종 I-FLOW로 확인.
- C-AC-06: 세 영역, focus와 입력 owner 별도 표시. `P-C-AC-06`와 최종 I-COMPAT로 확인.
- C-AC-14: 두 원본 OMP TUI·명령 유지. `P-C-AC-14`와 최종 I-COMPAT로 확인.

## 계약과 선행 산출물

CW-05의 PTY/VT snapshot·input routing 계약과 CW-17의 `ui_v1` attach·display stream·input/paste/resize·인수·자동화 상태 계약을 그대로 소비한다. Focus 변경은 host 입력 owner 변경이 아니다. OMP 화면을 일반 채팅 view로 대체하지 않는다. Shell/pause 상태는 CW-05 port와 fixture로 렌더링 검증하고 실제 production 상태 연결은 CW-12/15/16에서 확인한다. UI 위치·단축키는 이 계획으로 고정하지 않는다.

선행 산출물·통합 경계는 PLAN의 이 ticket 및 `dependency_artifacts`를 따른다.

- CW-05: G4 frontend/backend 계약과 terminal 렌더링이 통합·검증됨.
- CW-17: production backend·진입점·`ui_v1` 계약이 통합·검증됨.

계획 write scope: `src/workbench/ui/**`, `tests/ui/**`. 실제 dispatch 전에 Root가 current base·mutation lease·resource claim을 재확인한다.

## 검증

실제 진입점으로 시작한 backend의 두 OMP에서 목표·코드 대화와 slash command·composer/approval 조작을 하고 세 pane 전환·resize/화면 복원·UI 종료 후 재attach 화면 복원을 확인한다. 독립 test_designer가 키 충돌/붙여넣기 사례를 추가하고 reviewer가 원본 TUI fidelity를 확인한다.

소유 check의 기준은 `PLAN.gate_items`다. 아래는 해당 항목의 요약이며 supplier/evidence의 원본은 PLAN이다.

| Item | 필요 근거 | 관측 |
|---|---|---|
| P-C-AC-01 | runtime | 원본 manager OMP pane에서 목표·코드 대화 |
| P-C-AC-06 | runtime | 세 영역, focus와 입력 owner 별도 표시 |
| P-C-AC-14 | runtime | 두 원본 OMP TUI·명령 유지 |

Worker quick check → 독립 `test_designer` 평가/필요 테스트 → 필수 실패가 해결된 후보 동결 → fresh `reviewer` → 필요한 delta 검증 → Root 통합. 기존 review는 유효 범위와 함께 재사용한다. 각 명령·cwd·candidate·요구 digest·환경·exit code·결과·unknown을 기록한다. Runtime probe는 PTY/pipe drain과 bounded cleanup/잔존 확인을 포함한다.
