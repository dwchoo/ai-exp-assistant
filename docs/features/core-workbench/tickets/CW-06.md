# CW-06: 세 영역 원본 OMP 조작

명세: [SPEC.md](../SPEC.md) s2.2. Scheduling·resource·scope의 원본: [PLAN.json](../PLAN.json) CW-06 항목. Live 상태와 작업 배정은 Root의 별도 workflow state에서 관리한다.

## 제공할 동작

원본 manager OMP·worker OMP와 실제 host terminal을 한 화면에 표시하고 사용자 direct chat, focus, host 입력 owner, 상태·마지막 확인 시각을 분리해 보여준다.

## 수락 기준

- C-AC-01: 원본 manager OMP pane에서 목표·코드 대화. 최종 I-FLOW에서 재확인.
- C-AC-06: 세 영역, focus와 입력 owner 별도 표시. 최종 I-COMPAT에서 재확인.
- C-AC-14: 두 원본 OMP TUI·명령 유지. 최종 I-COMPAT에서 재확인.

## 계약과 선행 산출물

- CW-05: G4 frontend/backend 계약과 terminal 렌더링이 통합·검증됨.

CW-05의 PTY/VT snapshot·input routing 계약을 그대로 소비한다. Focus 변경은 host 입력 owner 변경이 아니다. OMP 화면을 일반 채팅 view로 대체하지 않는다.

계획 write scope: `src/workbench/ui/**`, `tests/ui/**`. 실제 dispatch 전에 Root가 current base·소유권·resource claim을 다시 확인한다.

## 검증

실제 두 OMP에서 목표·코드 대화와 slash command·composer/approval 조작을 하고 세 pane 전환·resize/화면 복원을 확인한다. 독립 test_designer가 키 충돌/붙여넣기 사례를 추가하고 reviewer가 원본 TUI fidelity를 확인한다.

공통 검증: worker quick check → 독립 test_designer 평가/필요 테스트 → 동결 후보 fresh reviewer → 필요한 수정·delta review → Root 통합 및 SPEC의 최종 check. 명령·cwd·candidate·환경·결과를 기록한다.

## 범위 밖과 중단 조건

G1/G4 고정 조합을 깨거나 미시험 단축키 지원을 주장해야 하면 멈추고 차이를 기록한다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 제품 동작 확대는 이 ticket의 범위가 아니다.

## 산출물 인계

변경 경로와 근거를 특정한 candidate/output bundle, 실제 수행한 check와 미실행 사유, 실패·미확인 gate/acceptance, 다음 ticket이 소비할 계약 변경점을 Root에게 전달한다. Ticket 작성자가 PLAN/state/approval을 직접 바꾸지 않는다.
