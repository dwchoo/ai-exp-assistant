# CW-04: G3 독립 OMP bridge

명세: [SPEC.md](../SPEC.md) s2.6, 입력 [BRIEF r1.13](../BRIEF.md). 기존 r1.12/s2.5/p2.5 승인에 [C-D55](../DECISION-2026-09-26.md)를 반영했다. 현재 요청은 문서화·인계이며 다음 세션에서 실제 상태·회계를 대조한 뒤 구현한다.
Scheduling·resource·write scope의 원본: [PLAN.json](../PLAN.json) `CW-04`. Live 상태/배정은 Root workflow record에서 관리한다.

## 제공할 동작

실제 두 OMP TUI의 composer/session/전달 성공·비동기 오류와 C-D49 turn 중단 경계를 검증한다. Public API 복귀를 OMP 처리 완료로 표시하지 않는다. 일반 경로의 후속 오류 보고, event의 원래 session/run/turn 출처 또는 unknown, 같은 process 재접속 상태 snapshot, report/reply identity를 포함한 bridge 후보와 evidence를 제공한다.

## 수락 기준

- 초기 feasibility 산출물이다. 아래 소유 항목을 실제 관측하고 독립 검증하며, 연결된 C-AC의 최종 제품 완료를 여기서 선언하지 않는다.

## 계약과 선행 산출물

CW-01 envelope 유지. 공개 API만 사용하고 native approval을 우회하는 mutable tool wrapper를 재도입하지 않는다. `api_returned`/해당 ID 입력 관측/structured report/업무 완료를 구분하고 현재 role/session/generation·idle/pending/approval/composer를 재확인한다. Callback 시점의 mutable current session을 지연 event의 원래 출처로 쓰지 않는다. 출처를 공개 API에서 확인할 수 없으면 unknown으로 남긴다. RPC `getEditorText()` 빈 값은 TUI 입력 근거가 아니다. 같은 process 재접속과 session 전환은 이 ticket, process 재시작 durable 복구는 CW-09/15다.

선행 산출물·통합 경계는 PLAN의 이 ticket 및 `dependency_artifacts`를 따른다.

- CW-01: role/message/session 계약과 게이트 harness가 통합·검증됨.

계획 write scope: `omp_bridge/**`, `src/workbench/ipc/bridge_*/**`, `tests/gates/g3_*/**`, `docs/features/core-workbench/gates/G3.md`. 실제 dispatch 전에 Root가 current base·mutation lease·resource claim을 재확인한다.

현재 partial/실패 근거: [G3](../gates/G3.md), [진단 d2](../DIAGNOSIS.md). 동일 입력/행동의 유효 근거만 재사용하며 기존 실패를 새 pass로 덮지 않는다.

## 검증

기존 Node/Python fixture와 실제 TUI/provider/pause/reconnect의 해당 partial 근거를 보존한다. 실제 두 TUI에서 composer 초안·focus·busy·native approval의 진입/유지/해제, 공개 API 복귀 뒤 성공/비동기 오류, ID로 확인한 처리 관측을 시험한다.

Assistant error 요약을 opt-in 진단 경로에만 묶지 않고 일반 경로에서 host가 관측할 수 있게 한다. 보고 전 HTTP·인증·네트워크·abort·process 오류와 보고 후 남은 도구/후손을 구분하며 익명 오류를 특정 요청 실패로 단정하지 않는다. Structured report/reply는 원 요청 message ID·task/revision/run과 보고 자체 ID를 연결해 수신 측이 유효한 요청과 대조한다. Public event의 원래 출처가 확인되지 않으면 unknown/no replay를 유지하고, 필요한 정상 처리 관측까지 생략한 채 gate를 통과시키지 않는다.

Session switch와 동일 process reconnect/ACK 유실/지연 중복을 수명 경계별로 검증한다. 연결 단절 동안 event를 버리고 완료로 처리하지 않으며 reconnect snapshot으로 미해결 상태를 재조회한다. 실제 TUI manager의 진행 turn에 pause를 보내 요청/turn 종료/unknown tool 결과를 분리하고 harness의 파일·tool·process·task·승인 대조 뒤 명시적 resume만 허용한다. 새 자동 manager/worker 전달 보류와 no replay를 확인한다. 60초 worker 점검/실제 backend 사용자 표시는 CW-11/12 및 최종 통합 소유다.

소유 check의 기준은 `PLAN.gate_items`다. 아래는 해당 항목의 요약이며 supplier/evidence의 원본은 PLAN이다.

### 먼저 확인할 가정과 최소 실험

`PLAN.feasibility_experiments.E-G3-TUI`를 따른다.

- 가정: 공개 OMP TUI API로 사용자 composer를 보존하면서 식별 가능한 메시지 전달·실패/불명·session 전환을 관측할 수 있다.
- 최소 실제 실험: 고정 18.2.10 두 실제 TUI에서 non-empty draft→자동 요청 보류→사용자가 draft 정리 후 새 요청 처리 관측. 정상 전달과 API 복귀 후 scripted provider/전송 비동기 오류를 짝지어 message/session ID·provider 입력·event·초안/focus를 비교한다.
- 성공 후: session switch·동일 process 재연결·ACK 손실 및 C-D49 실제 TUI pause/reconcile harness로 확대.
- 실패 시: public API 관측 범위에서 상태 의미와 bridge를 수정한다. native approval 우회 wrapper 금지. 사용자 초안 침범을 해결할 수 없으면 관련 전개 차단.
- 미확인 시: RPC 빈 editor 값을 TUI 근거로 쓰지 않는다. OMP 처리 identity를 관측할 수 없는 단계는 unknown으로 두고 replay 금지.

Worker quick check → 독립 `test_designer` 평가/필요 테스트 → 필수 실패가 해결된 후보 동결 → fresh `reviewer` → 필요한 delta 검증 → Root 통합. 기존 review는 유효 범위와 함께 재사용한다. 각 명령·cwd·candidate·요구 digest·환경·exit code·결과·unknown을 기록한다. Runtime probe는 PTY/pipe drain과 bounded cleanup/잔존 확인을 포함한다.

## 범위 밖과 중단 조건

실제 TUI 초안/approval 침범, session 유입, method 반환을 처리 완료로 저장하는 후보는 통과하지 않는다. 일반 오류 보고·원 출처·reconnect snapshot·report identity 중 required item을 관측하지 못하면 unknown을 보존하고 관련 전개를 차단한다. 모든 provider 오류의 확정 귀속이 실제 필수인데 공개 API가 이를 제공하지 않는 경우에만 API/지원 버전 변경안을 제시한다. Native approval 우회 wrapper를 재도입하지 않는다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 동작 확대는 범위 밖이다. Gate item은 이 ticket 또는 전이적 선행 산출물만 사용한다. 후속 통합의 책임을 초기 통과 조건으로 요구하지 않는다.

## 산출물 인계

귀속 가능한 candidate/output bundle, 변경 경로, 수행한 check와 미실행 이유, 실패/unknown, 소비할 계약·지원 조합을 Root에 전달한다. PLAN/state/approval은 Root만 수정한다. Ticket 상태만으로 acceptance 완료를 표시하지 않는다.
