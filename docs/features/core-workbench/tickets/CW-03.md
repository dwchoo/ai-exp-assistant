# CW-03: G2 관리된 same-shell control 대기와 인수

명세: [SPEC.md](../SPEC.md) s2.4, 입력 [BRIEF r1.11](../BRIEF.md). 최초 구현 승인과 C-D53 정책 개정은 현재 run의 승인 기록을 따른다.
Scheduling·resource·write scope의 원본: [PLAN.json](../PLAN.json) `CW-03`. Live 상태/배정은 Root workflow record에서 관리한다.

## 제공할 동작

관리된 Bash/dash가 wb-handoff 뒤 prompt로 돌아가지 않고 전용 control 경로에서 한 요청을 수락·실행하는지 먼저 입증한다. PID/cwd/export/검증한 환경 보존, 일반 입력·job 경합 보류, 인수 요청/확인 및 이미 전달된 명령의 불명 처리를 확인한다. Shell 평가 반환과 관리 대상 local process의 종료 확인·unknown을 구분하고 확인 가능한 exit status를 기록한다. 로그를 해석해 실험 성공을 판정하지 않는다.

## 수락 기준

- 초기 feasibility 산출물이다. 아래 소유 항목을 실제 관측하고 독립 검증하며, 연결된 C-AC의 최종 제품 완료를 여기서 선언하지 않는다.

## 계약과 선행 산출물

C-D48/C-D50..53 및 ADR-0002. 고의적 내부 변조/event 위조는 보안 경계 밖이며 비호환 hook/trap와 일반 경합은 필수 검증. Backend 전송/수락/시작/shell 반환/관리 대상 종료 확인 또는 unknown을 분리하고 PTY stdin과 control을 분리한다. 인수 즉시 새 전송 금지, 기존 실험 유지, 확인된 foreground 대상의 수동 입력, 오래된 요청 replay 금지. 최초 자동화는 C-AC-29, 수동 개입 뒤만 명시적 wb-handoff. Delegated cgroup 필수 여부는 미결정이며 현재 안전 결함도 별도 차단 상태다.

선행 산출물·통합 경계는 PLAN의 이 ticket 및 `dependency_artifacts`를 따른다.

- CW-01: command ID·lifecycle·입력 owner의 임시 계약이 통합·검증됨.

계획 write scope: `src/workbench/terminal/shell_*/**`, `tests/gates/g2_*/**`, `docs/features/core-workbench/gates/G2.md`. 실제 dispatch 전에 Root가 current base·mutation lease·resource claim을 재확인한다.

현재 partial/실패 근거: [G2](../gates/G2.md), [진단 d2](../DIAGNOSIS.md). 동일 입력/행동의 유효 근거만 재사용하며 기존 실패를 새 pass로 덮지 않는다.

## 검증

기존 26개 시험과 4개 실패를 사례별로 C-D50의 일반 경합·비호환 설정·고의적 내부 변조로 분류한 표를 남긴다. 원본 실패 근거는 보존하고 지원 밖 분류만으로 정상 입력/job 경합을 면제하지 않는다. 실제 Bash/dash에서 정상 cd/export와 conda·venv activation/deactivation, 직접 wb-handoff, stdin과 control 분리, stale generation, 미소비 입력/REPL/background/suspend, hook/trap 비호환 보류를 확인한다. 전송 전·전송 후·수락 후·시작 후 및 ACK 유실 각각에서 인수 요청/확인·명령 상태·foreground 수동 입력을 검증한다. Ctrl-C/exec/control 손실/종료와 첫 Bash 부재→sh 시작도 실제로 확인한다.

소유 check의 기준은 `PLAN.gate_items`다. 아래는 해당 항목의 요약이며 supplier/evidence의 원본은 PLAN이다.

### 먼저 확인할 가정과 최소 실험

`PLAN.feasibility_experiments.E-G2-CONTROL`를 따른다.

- 가정: 같은 interpreter가 prompt로 복귀하지 않는 control 대기를 소유하면 일반 입력/job 경합을 막으면서 정상 cwd/export 실행과 foreground 인수를 지원할 수 있다.
- 최소 실제 실험: 격리된 실제 Bash와 /bin/sh→dash 각각에 manual cd/export→직접 wb-handoff→전용 control로 명령 1개→수락/시작/종료와 PID/cwd/env를 관측. 같은 harness에서 background/suspend/입력 대기 hook과 takeover 전송 전·전송 후/ACK 유실, stdin 읽는 foreground job의 인수·수동 입력을 짝지어 확인한다.
- 성공 후: 실행권 소유 지점·정상 성공·부정 사례가 모두 입증되면 환경/hook/signal matrix와 adapter를 확대한다. G2 전체 item 통과 전 production으로 확장하지 않는다.
- 실패 시: READY 검사 보강을 반복하지 않고 실패한 실행권 가정을 기록한다. 현재 사용자 행동을 유지하는 새 가설이 없으면 해당 ticket 차단. 사용자 동작 변경만 가능하면 refine-spec.
- 미확인 시: PTY/control drain·bounded cleanup·판별법 결함을 먼저 구분한다. 새 관측을 낼 한정된 probe 수정만 허용하며 제품 확장 보류.

Worker quick check → 독립 `test_designer` 평가/필요 테스트 → 필수 실패가 해결된 후보 동결 → fresh `reviewer` → 필요한 delta 검증 → Root 통합. 기존 review는 유효 범위와 함께 재사용한다. 각 명령·cwd·candidate·요구 digest·환경·exit code·결과·unknown을 기록한다. Runtime probe는 PTY/pipe drain과 bounded cleanup/잔존 확인을 포함한다.

## 범위 밖과 중단 조건

정상 성공 또는 일반 race/인수 시나리오를 성립시키지 못하면 제품 확장을 멈춘다. 비호환 탐지를 가정하거나 all-deny 후보를 성공으로 쓰지 않는다. 새 증거 없는 READY 검사 보강 반복, 별도 runner shell 우회, sh 지원 축소는 진행하지 않는다. 사용자 동작 변경이 필요한 대안은 재합의한다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 동작 확대는 범위 밖이다. Gate item은 이 ticket 또는 전이적 선행 산출물만 사용한다. 후속 통합의 책임을 초기 통과 조건으로 요구하지 않는다.

## 산출물 인계

귀속 가능한 candidate/output bundle, 변경 경로, 수행한 check와 미실행 이유, 실패/unknown, 소비할 계약·지원 조합을 Root에 전달한다. PLAN/state/approval은 Root만 수정한다. Ticket 상태만으로 acceptance 완료를 표시하지 않는다.
