# CW-03: G2 부모 shell control 대기와 실험 supervisor

명세: [SPEC.md](../SPEC.md) s2.6, 입력 [BRIEF r1.13](../BRIEF.md). 기존 r1.12/s2.5/p2.5 승인에 [C-D55](../DECISION-2026-09-26.md)를 반영했다. 현재 요청은 문서화·인계이며 다음 세션에서 실제 상태·회계를 대조한 뒤 구현한다.
Scheduling·resource·write scope의 원본: [PLAN.json](../PLAN.json) `CW-03`. Live 상태/배정은 Root workflow record에서 관리한다.

## 제공할 동작

관리된 부모 Bash/dash가 `wb-handoff` 뒤 prompt로 돌아가지 않고 control 대기에 머무는 동안 고정 supervisor/subreaper가 별도 interpreter 또는 executable로 실험 전체를 실행하는 구조를 입증한다. 부모 PID·준비된 cwd·exported environment, 일반 입력·job 경합 보류, 인수 요청/확인, 이미 전달된 명령의 불명 처리를 유지한다.

주 프로그램 반환, 전체 관리 대상 후손 종료·회수 또는 `unknown`, 입력 반환 장벽, 부모 control 복귀를 구분하고 확인 가능한 exit status를 기록한다. 로그를 해석해 실험 성공을 판정하지 않는다.

## 수락 기준

- 초기 feasibility 산출물이다. 아래 여섯 소유 항목을 실제 관측하고 독립 검증하며, 연결된 C-AC의 최종 제품 완료를 여기서 선언하지 않는다.
- 입력 반환·signal·subreaper 최소 합성 판별이 먼저 통과해야 환경·인수·장애·launch matrix와 production adapter로 확장한다. 기존 단독 probe의 통과 수를 합산해 이 선행 조건을 충족했다고 보지 않는다.

## 계약과 선행 산출물

C-D48/C-D50..54와 [ADR-0002](../../../adr/0002-managed-shell-control-wait.md)를 따른다. 고의적 내부 변조/event 위조는 보안 경계 밖이며 비호환 hook/trap, 일반 경합, 수동 잔존과 상태 불명은 필수 검증이다.

부모 control 경로는 고정 helper만 시작한다. 단순 argv는 불필요한 shell 재해석 없이 실행할 수 있고 복잡한 script는 전체가 자식 interpreter 안에서 평가된다. Pipeline·명령 치환·redirection을 부모가 먼저 실행하지 않는다. 부모의 cwd/exported environment는 자식에 상속하지만 실험 내부 cd·export·source는 부모에 자동 반영하지 않는다. Supervisor는 실행 전에 subreaper 설정 성공을 확인하고 실험 하나만 담당한다.

후손 종료 근거에는 후보의 단일 reaper 권한, wait 범위, SIGCHLD disposition, 자식 signal disposition의 상속·정규화, 추가 spawn 가능성의 폐쇄 조건을 기록한다. 정상 자식의 signal 반응, 빠른 fork/exit, 주 프로그램 종료와 후손 생성 경합을 음성 대조와 함께 확인한다. 관측 범위 밖 생성 방식은 완료로 숨기지 않고 `unknown` 또는 지원 보류로 남긴다.

Backend 전송/수락/supervisor 시작/실험 시작/주 프로그램 반환/전체 후손 종료 또는 unknown/입력 반환/부모 control 복귀를 분리한다. PTY stdin과 control을 분리하고, 인수 즉시 새 전송을 금지하며, 기존 실험을 유지하고, 확인된 foreground 대상에만 수동 입력을 보내며, 오래된 요청을 replay하지 않는다. 최초 자동화는 C-AC-29, 수동 개입 뒤만 명시적 `wb-handoff`를 사용한다. C-D55에 따라 delegated cgroup을 core 필수 조건으로 추가하지 않는다. 자동 실험의 관리 대상 후손을 추적하되 수동 daemon의 발견·소급 관리를 보장하지 않는다. 수명 불명은 unknown/자동 후속 실행 보류이며 사용자 확인만으로 종료 완료로 바꾸거나 귀속 불명 프로세스를 자동 종료하지 않는다.

선행 산출물·통합 경계는 PLAN의 이 ticket 및 `dependency_artifacts`를 따른다.

- CW-01: command ID·lifecycle·입력 owner의 임시 계약이 통합·검증됨.

계획 write scope: `src/workbench/terminal/shell_*/**`, `tests/gates/g2_*/**`, `docs/features/core-workbench/gates/G2.md`. 실제 dispatch 전에 Root가 current base·mutation lease·resource claim을 재확인한다.

현재 근거는 [G2](../gates/G2.md), [진단 d2](../DIAGNOSIS.md), [직접 eval recovery 결과](../../../../.workflow/core-workbench/runs/implement-p2.3-20260924/cw03-recovery-root-result.json), [RUN 경계 실패](../../../../.workflow/core-workbench/runs/implement-p2.3-20260924/cw03-recovery-edge-root-result.json), [Oracle 검토](../../../../.workflow/core-workbench/runs/oracle-review-20260924/REVIEW.md)다. EOF·WAIT recovery 일부와 A/subreaper 단독 probe의 유효 근거는 해당 입력에 한정해 보존한다. Bash/dash `return` 입력 유출과 Ctrl-C 오류는 새 후보의 필수 음성 대조다.

## 검증

C-D55에 따라 conda 전용 점검과 환경 관리자별 activation/deactivation matrix는 제외한다. 일반 환경 상속·비전파와 정상 수동 준비·비호환 hook/trap 보류는 runtime으로 검증한다. 기존 venv 근거는 보존하되 관리자별 matrix를 확대하지 않는다.

### 1. 선행 최소 합성 판별

임의 sleep 대신 시험용 barrier로 전환 직전·직후를 고정한다. 같은 후보에서 다음을 결합한다.

| 대상 | 최소 사례 | 통과 기준 |
|---|---|---|
| 실행 범위 | 정상 argv/script, Bash/dash `return`, `exec`, pipeline, 명령 치환 | 부모 controller·PID·cwd/export 유지, 실험 전체가 자식 범위, prompt 입력 유출 없음 |
| 후손 수명 | 주 프로그램 종료 뒤 double-fork/setsid 후손 생존, 빠른 fork/exit, 종료와 추가 spawn 경합 | 단일 reaper·wait 범위·SIGCHLD disposition·spawn 폐쇄 조건이 기록됨. 생존 중 완료 없음, 전체 종료·회수 후 수명 종료, 잘못된 `WNOHANG`/`ECHILD` 판정의 음성 대조 통과 |
| Signal·PG | 시작·실행·반환 장벽·부모 WAIT의 Ctrl-C, SIGQUIT, Ctrl-Z/재개 | 관측자 유지 또는 명시적 unknown, suspend와 exit 구분, 기본 untrapped script의 Ctrl-C 뒤 tail 없음 |
| 입력 반환 | `dd` 잔여 입력, key/paste/부분 write/terminal query reply, `wb-handoff`와 후속 줄을 한 write/paste, foreground 확인 직후 종료 | 장벽 진입→이전 writer 차단·정리→같은 부모 shell의 실제 읽기·prompt 복귀→새 정상 입력 처리 뒤에도 독립 marker 부작용 없음. 알려진 유출 후보에서는 marker가 생김 |
| 장애 | 실험 생존 중 supervisor 사망, control/recovery/event FD 손실 | 전체 종료를 선언하지 않고 `unknown`; 새 supervisor가 기존 후손을 소급 복구했다고 표시하지 않음 |
| 수동 단계 | 정상 수동 준비 뒤 handoff, 수동 daemon 잔존 | 정상 사례는 성공하고 불명 잔존은 자동 수락하지 않음 |

공유 foreground process group 후보부터 검증한다. 관측자 정지나 job-control 충돌이 확인될 때만 supervisor/experiment process group 분리와 `tcsetpgrp`·SIGTTIN/SIGTTOU 동작을 제한적으로 비교한다. `TCIFLUSH`, ACK, fresh READY만으로 shell parser나 Workbench queue가 비었다고 판단하지 않는다.

### 2. 전체 G2 matrix

선행 합성 판별이 통과한 경로에 사용자 직접 준비한 cwd·PATH·exported environment 상속·비전파, 비호환 hook/trap 보류, 여러 줄·미제출 입력·REPL·background/suspend·stale owner/generation, 전송 전/후·수락/시작 후·ACK 유실 인수, 정상/비정상 exit·flush 실패·no replay, Bash 우선/sh fallback을 결합한다.

소유 check의 원본은 `PLAN.gate_items`다.

| Item | 필요 근거 | 관측 |
|---|---|---|
| G2-CONTROL | runtime | 부모 Bash/dash의 직접 `wb-handoff`와 control 대기, 고정 supervisor의 별도 interpreter/executable 실행, 요청 수락·supervisor/실험 시작·주 프로그램 반환·전체 후손 종료/unknown·입력 반환·부모 control 복귀, PID/cwd/export 보존과 stdin/control 분리 |
| G2-INPUT-JOBS | runtime | 여러 줄·미제출 입력·REPL·background/suspended job·stale generation/owner와 key/paste/부분 write/query reply, handoff+후속 줄 단일 write에서 자동 수락·입력 유출 없음. 같은 부모 prompt 복귀와 새 정상 입력 뒤 marker 부재 및 알려진 유출 후보의 marker 발생. 항상 거절하는 후보도 실패 |
| G2-HOOK-ENV | runtime | 사용자가 준비한 cwd·PATH·exported environment 상속과 실험 내부 상태 비전파, 비호환 hook/trap·수동 잔존 보류, 기존 실패 분류 |
| G2-TAKEOVER | runtime | 전송 전/후·수락/시작 후·ACK 유실, foreground 종료 경합에서 새 전송 금지·요청/확인 구분·확인 대상 입력·unknown/no replay·입력 반환 장벽 |
| G2-LIFECYCLE | runtime | 정상/비정상 exit, double-fork/setsid, 빠른 fork/exit와 종료·spawn 경합, Ctrl-C/SIGQUIT/suspend/resume, FD/flush/supervisor 장애에서 주 프로그램·전체 후손·입력 반환·unknown 구분. 단일 reaper·wait 범위·SIGCHLD 및 자식 signal disposition 근거를 기록하고 수동 daemon·관측 밖 생성 공백을 성공으로 숨기지 않음 |
| G2-LAUNCH | runtime | Bash 우선, Bash 없는 PATH의 실제 sh, 둘 다 없을 때 안내, 선택 실행 파일과 supervisor 경로 고정, 실행 실패의 새 shell 우회 없음 |

Worker quick check → 독립 `test_designer` 평가/필요 테스트 → 필수 실패가 해결된 후보 동결 → fresh `reviewer` → 필요한 delta 검증 → Root 통합 순서다. 기존 review는 유효 범위와 함께 재사용한다. 각 명령·cwd·candidate·요구 identity·환경·exit code·결과·unknown을 기록한다. Runtime probe는 PTY/pipe drain, bounded deadline, owned process group cleanup과 잔존 확인을 포함한다.

## 범위 밖과 중단 조건

정상 성공 또는 입력 반환·signal·후손 수명·인수 반례 중 하나를 성립시키지 못하면 제품 확장을 멈춘다. 비호환 탐지나 all-deny 후보를 성공으로 쓰지 않는다. 부모 직접 eval로 돌아가거나 단독 probe 통과 수를 합산하지 않는다. Same-PID 안전 복구·수동 잔존 관측이 불가능해 입력 방식, shell 지원, cgroup·추가 권한을 바꿔야 할 때만 근거와 대안을 사용자에게 제시한다.

이번 ticket의 Docker runtime 검증은 사용자 결정에 따라 생략한다. Container 호환성 목표는 유지하며 지원 완료로 표시하지 않는다. Phase 2·내부 tmux 등 external terminal multiplexer 의존·무단 commit/push/merge·미승인 동작 확대는 범위 밖이다.

## 산출물 인계

귀속 가능한 candidate/output bundle, 변경 경로, 수행한 check와 미실행 이유, 입력 반환·signal·subreaper 합성 결과, 실패/unknown, 소비할 계약·지원 조합을 Root에 전달한다. PLAN/state/approval은 Root만 수정한다. Ticket 상태만으로 acceptance 완료를 표시하지 않는다.
