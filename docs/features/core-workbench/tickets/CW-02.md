## 제공할 동작

G1의 정상 resize·3-pane 입력 routing·텍스트/색/approval·외부 terminal 조합을 실제 OMP에서 확인한다. 이미 유효한 approval/tool·외부 tmux·resize/fixture 근거는 동일 candidate/input 범위에서 보존한다. RGB 축소 경로의 실제 화면 영향을 원본 OMP와 대조하고 확인된 출력 경로만 최소 수정한다.

## 수락 기준

- 초기 feasibility 산출물이다. 아래 소유 항목을 실제 관측하고 독립 검증하며, 연결된 C-AC의 최종 제품 완료를 여기서 선언하지 않는다.

## 계약과 선행 산출물

CW-01 display/control 경계를 소비한다. 원본 OMP composer·승인·slash command와 한글·wide character·색·도구 출력이 유지되어야 한다. 내부 tmux/headless 대체는 허용되지 않는다.

선행 산출물·통합 경계는 PLAN의 이 ticket 및 `dependency_artifacts`를 따른다.

- CW-01: 임시 PTY/control 경계와 재현 가능한 게이트 harness가 통합·검증됨.

계획 write scope: `src/workbench/terminal/vt_*/**`, `src/workbench/ui/terminal_*/**`, `tests/gates/g1_*/**`, `docs/features/core-workbench/gates/G1.md`. 실제 dispatch 전에 Root가 current base·mutation lease·resource claim을 재확인한다.

현재 partial/실패 근거: [G1](../gates/G1.md), [진단 d2](../DIAGNOSIS.md). 동일 입력/행동의 유효 근거만 재사용하며 기존 실패를 새 pass로 덮지 않는다.

## 검증

기존 `tests/gates/g1_vt` fixture와 native approval/tool·외부 tmux·resize 실제 관측의 유효 근거를 재사용한다. 단일 OMP를 정지시키지 않는 resize와 판별법의 부정 대조부터 확인하고, 실제 두 OMP+host 3-pane outer resize 뒤 각 입력 대상·draft·approval을 확인한다. Query reply의 정확한 byte/FIFO는 fixture, 사용자 화면·입력은 runtime으로 구분한다.

원본 OMP와 Workbench의 pane rows/columns, OMP 버전, theme, TERM/COLORTERM, font를 맞춘다. 한글·wide 문자·긴 줄·composer·approval·tool 출력에서 색·구분·줄바꿈·잘림·겹침을 대조하고 RGB→256색 축소가 실제 차이를 만든 경로만 수정한다. 수정 뒤 cursor·SGR·redraw·alternate-screen 복원을 다시 확인한다. 시작 지연은 process→extension/bridge→setup/composer 시점을 분리해 기록하며 timeout 확대만으로 해결로 판정하지 않는다. 일반 terminal·비중첩 Herdr 근거가 없으면 pending으로 남긴다.

### 먼저 확인할 가정과 최소 실험

`PLAN.feasibility_experiments.E-G1-RESIZE`를 따른다.

- 가정: 현재 VT/renderer가 signal 정지 없이 실제 OMP 크기 변경 뒤 배치와 사용자 입력/승인 상태를 보존한다.
- 최소 실제 실험: 실제 OMP TUI에서 100x32→84x24→100x32, composer 한글 draft와 native approval/tool 출력 각각의 geometry/줄바꿈/잘림·겹침/입력·승인 상태를 관측. no-resize와 resize 전달 누락 부정 대조로 predicate 검증. 전체 출력 정숙을 강제하지 않는다.
- 성공 후: 두 OMP+host 실제 3-pane의 outer resize/후속 입력 대상과 일반 terminal/tmux/herdr matrix 검증으로 확대.
- 실패 시: 재현한 렌더링/입력 결함을 bounded 수정 또는 기존 범위 안의 VT 후보 교체로 처리. 내부 tmux/headless로 요구를 줄이지 않는다.
- 미확인 시: startup wizard/PTY drain/성공 predicate를 고쳐 재관측. STOP/CONT anchor나 파일 command preview를 통과로 쓰지 않는다.

Worker quick check → 독립 `test_designer` 평가/필요 테스트 → 필수 실패가 해결된 후보 동결 → fresh `reviewer` → 필요한 delta 검증 → Root 통합. 기존 review는 유효 범위와 함께 재사용한다. 각 명령·cwd·candidate·요구 digest·환경·exit code·결과·unknown을 기록한다. Runtime probe는 PTY/pipe drain과 bounded cleanup/잔존 확인을 포함한다.

## 범위 밖과 중단 조건

원본 TUI 핵심 조작이 실패하거나 실제 색상·일반 terminal·비중첩 Herdr 근거가 없으면 해당 item을 실패·미확인/pending으로 보고하고 UI production 구현으로 넘기지 않는다. 외부 tmux의 기존 통과는 변경 영향이 없는 입력·candidate 범위에서 재사용한다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 동작 확대는 범위 밖이다. Gate item은 이 ticket 또는 전이적 선행 산출물만 사용한다. 후속 통합의 책임을 초기 통과 조건으로 요구하지 않는다.

## 산출물 인계

귀속 가능한 candidate/output bundle, 변경 경로, 수행한 check와 미실행 이유, 실패/unknown, 소비할 계약·지원 조합을 Root에 전달한다. PLAN/state/approval은 Root만 수정한다. Ticket 상태만으로 acceptance 완료를 표시하지 않는다.
