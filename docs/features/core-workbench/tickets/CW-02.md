# CW-02: G1 원본 OMP TUI·VT 충실도

명세: [SPEC.md](../SPEC.md) s2.2. Scheduling·resource·scope의 원본: [PLAN.json](../PLAN.json) CW-02 항목. Live 상태와 작업 배정은 Root의 별도 workflow state에서 관리한다.

## 제공할 동작

G1: 원본 OMP 두 개와 host terminal의 실제 PTY stream을 세 pane에 표시하는 후보를 동작시켜 input, paste, resize, scrollback, query reply와 화면 복원을 실증한다.

사용자가 승인한 C-D47에 따라 2 MiB 한도 또는 queue 공간을 넘는 paste는 일부 전달 없이 전체 거절하고 화면에 이유를 표시한다. 거절 뒤에도 hotkey와 query reply를 처리한다.

## 수락 기준

- G1: 위 제공 동작을 실제 조건에서 검증하고 재현 가능한 통과·실패·미확인 근거를 남긴다. 수락 ID는 직접 소유하지 않으며 후속 C-AC 검증의 선행 증거다.

## 계약과 선행 산출물

- CW-01: 임시 PTY/control 경계와 재현 가능한 게이트 harness가 통합·검증됨.

CW-01 display/control 경계를 소비한다. 원본 OMP composer·승인·slash command와 한글·wide character·색·도구 출력이 유지되어야 한다. 내부 tmux/headless 대체는 허용되지 않는다.

계획 write scope: `src/workbench/terminal/vt_*/**`, `src/workbench/ui/terminal_*/**`, `tests/gates/g1_*/**`, `docs/features/core-workbench/gates/G1.md`. 실제 dispatch 전에 Root가 current base·소유권·resource claim을 다시 확인한다.

## 검증

고정 OMP 버전과 Linux terminal에서 키·한글·다중 행 붙여넣기·색·resize·alternate screen·detach 전후 화면을 실제 조작한다. Child가 읽지 않는 상태에서 paste 전체 거절·이유 표시·후속 F10 처리와 query reply 보존을 재현한다. 일반 terminal/tmux/herdr 중 실행한 조합과 미실행 조합을 구분해 G1.md에 남긴다. 독립 test_designer의 결함 사례와 reviewer의 VT/키 충돌 검토를 받는다.

공통 검증: worker quick check → 독립 test_designer 평가/필요 테스트 → 동결 후보 fresh reviewer → 필요한 수정·delta review → Root 통합 및 SPEC의 최종 check. 명령·cwd·candidate·환경·결과를 기록한다.

## 범위 밖과 중단 조건

원본 TUI 핵심 조작이 실패하거나 라이선스/설치 경로가 해결되지 않으면 G1 실패·미확인으로 보고하고 UI 생산 구현으로 넘기지 않는다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 제품 동작 확대는 이 ticket의 범위가 아니다.

## 산출물 인계

변경 경로와 근거를 특정한 candidate/output bundle, 실제 수행한 check와 미실행 사유, 실패·미확인 gate/acceptance, 다음 ticket이 소비할 계약 변경점을 Root에게 전달한다. Ticket 작성자가 PLAN/state/approval을 직접 바꾸지 않는다.
