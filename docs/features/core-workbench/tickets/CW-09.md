# CW-09: 영속 위임과 Task revision

명세: [SPEC.md](../SPEC.md) s2.2. Scheduling·resource·scope의 원본: [PLAN.json](../PLAN.json) CW-09 항목. Live 상태와 작업 배정은 Root의 별도 workflow state에서 관리한다.

## 제공할 동작

사용자 위임 승인·진행 지시를 TaskSpec revision과 연결하고 run/cancel 이력·세션 공통 설정을 durable metadata에 보존한다. CW-08이 사용할 Task/revision/run 연계 논리 메시지·전달 상태 기록 경계를 제공한다. 새 자동 실행은 승인 범위와 저장 성공이 확인된 때만 허용한다.

## 수락 기준

- C-AC-29: 범위 승인+진행 지시로 자동화 시작. 최종 I-POLICY에서 재확인.

## 계약과 선행 산출물

- CW-05: G4 Task/control 계약과 저장 경계가 통합·검증됨.

Task ID는 revision/commit 변경으로 재설정하지 않는다. 실행 중 명세 변경은 새 revision을 다음 run에 적용한다. 즉시 중단·권한 철회는 현재 run에 적용한다. 세션 공통 설정은 각 Task의 이후 판단에 적용하고 변경 전후 설정과 사용한 재시도 횟수의 연결을 보존한다. 안정된 `message_id`와 관련 Task/revision/run·전달 상태의 영속 기록 경계를 CW-08에 제공한다. Storage schema 변경은 이 ticket이 소유한다.

계획 write scope: `src/workbench/tasks/**`, `src/workbench/storage/metadata_*/**`, `tests/tasks/**`. 실제 dispatch 전에 Root가 current base·소유권·resource claim을 다시 확인한다.

## 검증

승인 전 실행 거절, 승인+진행 후 시작, revision 불변성, 취소 뒤 이전 revision 재실행 금지, metadata write failure에서 새 실행 보류를 검증한다. 동일 `message_id`의 논리 메시지와 별도 전달 상태 기록이 Task/revision/run에 연결되는지 확인한다. 실행 중 세션 설정을 바꿔도 현재 run을 종료하거나 사용한 재시도 횟수를 초기화하지 않으며 다음 판단에 새 설정을 연결하는지 확인한다. 독립 test_designer가 누락된 전이 사례를 작성하고 reviewer가 불변 기록을 점검한다.

공통 검증: worker quick check → 독립 test_designer 평가/필요 테스트 → 동결 후보 fresh reviewer → 필요한 수정·delta review → Root 통합 및 SPEC의 최종 check. 명령·cwd·candidate·환경·결과를 기록한다.

## 범위 밖과 중단 조건

승인 범위가 표현되지 않거나 metadata 쓰기 실패를 무시해야 실행 가능한 경우 중단한다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 제품 동작 확대는 이 ticket의 범위가 아니다.

## 산출물 인계

변경 경로와 근거를 특정한 candidate/output bundle, 실제 수행한 check와 미실행 사유, 실패·미확인 gate/acceptance, 다음 ticket이 소비할 계약 변경점을 Root에게 전달한다. Ticket 작성자가 PLAN/state/approval을 직접 바꾸지 않는다.
