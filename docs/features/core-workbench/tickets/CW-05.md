# CW-05: G4 detach 실증과 계약 고정

명세: [SPEC.md](../SPEC.md) s2.6, 입력 [BRIEF r1.13](../BRIEF.md). 기존 r1.12/s2.5/p2.5 승인에 [C-D55](../DECISION-2026-09-26.md)를 반영했다. 현재 요청은 문서화·인계이며 다음 세션에서 실제 상태·회계를 대조한 뒤 구현한다.
Scheduling·resource·write scope의 원본: [PLAN.json](../PLAN.json) `CW-05`. Live 상태/배정은 Root workflow record에서 관리한다.

## 제공할 동작

G1..G3 후보를 합친 최소 backend/frontend에서 세 PTY 수명 분리·재접속·실제 60초 OMP wake를 검증하고 control/관측/저장 port·dependency 조합을 고정한다. 요구 항목/입력 identity/evidence level을 판정하는 gate 집계 validator를 제공한다.

## 수락 기준

- 초기 feasibility 산출물이다. 아래 소유 항목을 실제 관측하고 독립 검증하며, 연결된 C-AC의 최종 제품 완료를 여기서 선언하지 않는다.

## 계약과 선행 산출물

CW-02..04 독립 검증 산출물을 소비한다. CW-03의 부모 control 대기·별도 실험 supervisor와 입력 반환/후손 수명, CW-04의 오류·출처·reconnect snapshot 의미를 최소 timer/Task 승인 fixture/저장 port와 결합한다. CW-09/11/12/15 production을 선행으로 요구하지 않는다. v1 공통 envelope는 보존하며 새 shell 상태·delivery 의미·pause/reconcile port를 versioned 확장/adapter로 명시하고 caller 계약을 함께 검증한다. 스키마만으로 gate를 통과시키지 않는다.

선행 산출물·통합 경계는 PLAN의 이 ticket 및 `dependency_artifacts`를 따른다.

- CW-02: G1 PTY/VT 후보와 실제 OMP 화면 증거가 통합·검증됨.
- CW-03: G2 입력 반환·signal·subreaper 최소 합성 판별과 전체 Bash/sh gate item이 통합·검증됨.
- CW-04: G3 공개 extension·session 전달·일반 오류/출처·같은 process 재접속 상태와 manager turn 중단 요청/확인 증거가 통합·검증됨.

계획 write scope: `src/workbench/runtime/**`, `src/workbench/contracts/**`, `src/workbench/app/**`, `tests/gates/g4_*/**`, `pyproject.toml`, `uv.lock`, `omp_bridge/package.json`, `docs/features/core-workbench/gates/G4.md`, `omp_bridge/contract/**`, `tests/contracts/**`, `tests/gates/harness/**`. 실제 dispatch 전에 Root가 current base·mutation lease·resource claim을 재확인한다.

## 검증

최소 frontend를 detach한 뒤 60초를 넘겨 같은 backend/두 OMP/부모 shell/실험 supervisor 상태와 실제 worker wake 처리, 재attach 중복 없음·입력 owner/control mode를 확인한다. 부모 shell·supervisor·실험 child identity를 구분하고 입력 반환 중 attach가 완료나 새 전송을 만들지 않게 한다. 최소 timer/pause port를 직접 구동하며 production CW-11/12/15를 기다리지 않는다. Metadata port 실패 주입과 확장 계약의 v1 호환/교차 언어 검증, 실제 dependency source/hash/license/설치 명령을 기록한다. 집계 validator는 PLAN required item 누락·잘못된 source/candidate digest·필수 unknown·fixture만 있는 runtime 항목을 거절해야 한다. G1..G3 근거를 현재 통합 입력에 연결한 뒤 production을 연다.

소유 check의 기준은 `PLAN.gate_items`다. 아래는 해당 항목의 요약이며 supplier/evidence의 원본은 PLAN이다.

|---|---|---|

### 먼저 확인할 가정과 최소 실험

`PLAN.feasibility_experiments.E-G4-LIFETIME`를 따른다.

- 가정: UI 수명과 backend/PTY/OMP/control 수명을 분리하고 사용자 owner·pause를 보존할 수 있다.
- 최소 실제 실험: 최소 frontend를 닫은 뒤 같은 backend/두 OMP/shell PID와 임시 host 실험을 60초 넘게 관측하고 실제 timer가 OMP worker 요청을 1회 처리하는지 확인한 뒤 재attach한다. 최소 pause port에서는 tick이 모델로 전달되지 않고 관측만 지속하는 대조를 수행한다.
- 성공 후: 계약/설치 조합/저장 port/evidence validator를 고정하고 CW-06/07/09로 전개.
- 실패 시: child 종료나 중복 시작이면 runtime 분리 가정을 수정하며 production 차단.
- 미확인 시: 모델/auth/host capability와 timer/PTY 결함을 분류하고 해당 관측만 재확인. CW-11/15 구현을 선행 요구로 만들지 않는다.

Worker quick check → 독립 `test_designer` 평가/필요 테스트 → 필수 실패가 해결된 후보 동결 → fresh `reviewer` → 필요한 delta 검증 → Root 통합. 기존 review는 유효 범위와 함께 재사용한다. 각 명령·cwd·candidate·요구 digest·환경·exit code·결과·unknown을 기록한다. Runtime probe는 PTY/pipe drain과 bounded cleanup/잔존 확인을 포함한다.

## 범위 밖과 중단 조건

G1..G3 소유 item의 필수 실패/unknown, 특히 CW-03 합성 판별이나 CW-04 오류·출처·snapshot 근거가 빠진 상태, 수명 분리·wake·재attach 중복 방지 실패, 집계 validator 부재/실패가 남으면 production frontier를 열지 않는다. 후속 production을 초기 gate의 선행으로 끌어와 순환을 만들지 않는다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 동작 확대는 범위 밖이다. Gate item은 이 ticket 또는 전이적 선행 산출물만 사용한다. 후속 통합의 책임을 초기 통과 조건으로 요구하지 않는다.

## 산출물 인계

귀속 가능한 candidate/output bundle, 변경 경로, 수행한 check와 미실행 이유, 실패/unknown, 소비할 계약·지원 조합을 Root에 전달한다. PLAN/state/approval은 Root만 수정한다. Ticket 상태만으로 acceptance 완료를 표시하지 않는다.
