# CW-11: 주기적 worker 점검과 hang 조사

명세: [SPEC.md](../SPEC.md) s2.3, 입력 [BRIEF r1.10](../BRIEF.md). 현재 묶음의 승인 기록은 [구현 승인](../../../../.workflow/core-workbench/runs/implement-p2.3-20260924/approval.json)이다.
Scheduling·resource·write scope의 원본: [PLAN.json](../PLAN.json) `CW-11`. Live 상태/배정은 Root workflow record에서 관리한다.

## 제공할 동작

자동화 활성 중 활성 run을 60초마다 worker 모델이 검토한다. Busy 시 최신 점검 하나만 유지하고 사용자 대화를 우선한다. 일시정지 중 새 모델 점검은 시작하지 않고 로그·프로세스 상태 수집은 계속한다. 종료 이벤트는 즉시 표시하고 hang 의심은 프로세스 근거로 조사한다.

## 수락 기준

- C-AC-12: 자동화 활성 중 60초 모델 점검·일시정지 중 모델 점검 중단·무출력 조사. `P-C-AC-12`와 최종 I-POLICY로 확인.
- C-AC-21: 활성 중 121번째 점검·13번째 peer wake·usage 표시. `P-C-AC-21`와 최종 I-POLICY로 확인.
- C-AC-27: 활성 중 busy 점검 최신 한 건·지연, 일시정지 중 자동 점검 보류·즉시 종료 표시. `P-C-AC-27`와 최종 I-POLICY로 확인.

## 계약과 선행 산출물

CW-10의 active run/session/exit event를 소비한다. 무출력·경과 시간 자체는 hang/종료가 아니다. Periodic review와 정상 peer wake에는 고정 횟수 상한이 없고 usage는 관측/추정을 구분한다. CW-05의 AutomationState/observation port를 사용하는 scheduler의 local pause 반응을 검증한다. 실제 사용자 pause→manager abort→reconcile 통합은 CW-12 소유이며 이를 CW-11의 선행 조건으로 요구하지 않는다.

선행 산출물·통합 경계는 PLAN의 이 ticket 및 `dependency_artifacts`를 따른다.

- CW-10: 활성 run·worker session·종료 이벤트 경로가 통합·검증됨.

계획 write scope: `src/workbench/observation/**`, `tests/observation/**`. 실제 dispatch 전에 Root가 current base·mutation lease·resource claim을 재확인한다.

## 검증

Clock seam으로 60초 tick, busy 최신 한 건, 사용자 대화·미제출 입력·승인 대기 우선, 지연/마지막 실제 점검, 종료 이벤트 즉시 표시를 검증한다. 121번째 점검·13번째 peer wake를 수행하고 사용량 미확인 표현을 확인한다. 일시정지 중 새 worker 모델 점검은 시작하지 않되 로그·프로세스 상태 수집은 지속하는 동작과 실제 OMP review를 확인하고 독립 test_designer/reviewer 근거를 남긴다.

소유 check의 기준은 `PLAN.gate_items`다. 아래는 해당 항목의 요약이며 supplier/evidence의 원본은 PLAN이다.

| Item | 필요 근거 | 관측 |
|---|---|---|
| P-C-AC-12 | runtime | 자동화 활성 중 60초 모델 점검·일시정지 중 모델 점검 중단·무출력 조사 |
| P-C-AC-21 | runtime | 활성 중 121번째 점검·13번째 peer wake·usage 표시 |
| P-C-AC-27 | runtime | 활성 중 busy 점검 최신 한 건·지연, 일시정지 중 자동 점검 보류·즉시 종료 표시 |

Worker quick check → 독립 `test_designer` 평가/필요 테스트 → 필수 실패가 해결된 후보 동결 → fresh `reviewer` → 필요한 delta 검증 → Root 통합. 기존 review는 유효 범위와 함께 재사용한다. 각 명령·cwd·candidate·요구 digest·환경·exit code·결과·unknown을 기록한다. Runtime probe는 PTY/pipe drain과 bounded cleanup/잔존 확인을 포함한다.

## 범위 밖과 중단 조건

사용자 composer/approval을 자동 주입이 침범하거나 무출력만으로 hang이라고 단정하면 중단한다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 동작 확대는 범위 밖이다. Gate item은 이 ticket 또는 전이적 선행 산출물만 사용한다. 후속 통합의 책임을 초기 통과 조건으로 요구하지 않는다.

## 산출물 인계

귀속 가능한 candidate/output bundle, 변경 경로, 수행한 check와 미실행 이유, 실패/unknown, 소비할 계약·지원 조합을 Root에 전달한다. PLAN/state/approval은 Root만 수정한다. Ticket 상태만으로 acceptance 완료를 표시하지 않는다.
