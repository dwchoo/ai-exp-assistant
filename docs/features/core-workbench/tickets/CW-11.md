# CW-11: 주기적 worker 점검과 hang 조사

명세: [SPEC.md](../SPEC.md) s2.2. Scheduling·resource·scope의 원본: [PLAN.json](../PLAN.json) CW-11 항목. Live 상태와 작업 배정은 Root의 별도 workflow state에서 관리한다.

## 제공할 동작

자동화 활성 중 활성 run을 60초마다 worker 모델이 검토한다. 일시정지 중에는 새 tick과 pending 모델 점검을 시작하지 않고 로그·프로세스 상태 수집을 계속한다. Busy 시 최신 점검 하나만 유지하고 사용자 대화를 우선하며, 종료 이벤트는 즉시 표시한다. Hang 의심은 프로세스 근거로 조사한다.

## 수락 기준

- C-AC-12: 활성 중 60초 모델 점검·일시정지 중 보류·무출력 조사. 최종 I-POLICY에서 재확인.
- C-AC-21: 121번째 점검·13번째 peer wake·usage 표시. 최종 I-POLICY에서 재확인.
- C-AC-27: 활성 중 busy 점검 최신 한 건·지연, 일시정지 중 자동 점검 보류·즉시 종료 표시. 최종 I-POLICY에서 재확인.

## 계약과 선행 산출물

- CW-10: 활성 run·worker session·종료 이벤트 경로가 통합·검증됨.

CW-10의 active run/session/exit event를 소비한다. 무출력·경과 시간 자체는 hang/종료가 아니다. Periodic review와 정상 peer wake에는 고정 횟수 상한이 없고 usage는 관측/추정을 구분한다.

계획 write scope: `src/workbench/observation/**`, `tests/observation/**`. 실제 dispatch 전에 Root가 current base·소유권·resource claim을 다시 확인한다.

## 검증

Clock seam으로 60초 tick, busy 최신 한 건, 사용자 대화·미제출 입력·승인 대기 우선, 지연/마지막 실제 점검, 종료 이벤트 즉시 표시를 검증한다. 121번째 점검·13번째 peer wake를 수행하고 사용량 미확인 표현을 확인한다. 일시정지 중 새 worker 모델 점검은 시작하지 않되 로그·프로세스 상태 수집은 지속하는 동작과 실제 OMP review를 확인하고 독립 test_designer/reviewer 근거를 남긴다.

공통 검증: worker quick check → 독립 test_designer 평가/필요 테스트 → 동결 후보 fresh reviewer → 필요한 수정·delta review → Root 통합 및 SPEC의 최종 check. 명령·cwd·candidate·환경·결과를 기록한다.

## 범위 밖과 중단 조건

사용자 composer/approval을 자동 주입이 침범하거나 무출력만으로 hang이라고 단정하면 중단한다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 제품 동작 확대는 이 ticket의 범위가 아니다.

## 산출물 인계

변경 경로와 근거를 특정한 candidate/output bundle, 실제 수행한 check와 미실행 사유, 실패·미확인 gate/acceptance, 다음 ticket이 소비할 계약 변경점을 Root에게 전달한다. Ticket 작성자가 PLAN/state/approval을 직접 바꾸지 않는다.
