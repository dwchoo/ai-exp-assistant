## 검증

실제 두 OMP·persistent host shell에서 목표→승인→worktree/run→60초 점검→완료·실패 복구, worker 직접 요청의 기존 범위·새 작은 명세·범위 확대 경계, 세션 설정 변경 후 현재 run/재시도 유지, 수동 제어, detach, 저장/모델 장애를 시험한다. C-AC-19/20은 일반 terminal/tmux/herdr와 Bash·실제 sh matrix를 조작하고 기본/login shell이 zsh인 경우, Bash/sh가 둘 다 없는 경우의 안내를 검증한다. 누락된 service/capability는 pending으로 남긴다. test_designer와 fresh reviewer 및 최종 checks를 실행한다. C-D50..52의 정상 handoff·control 대기·환경 전환·전송 중 인수/foreground 수동 입력을 최종 UI/backend에서 확인한다. I-* 다섯 항목을 34개 C-AC 모두에 연결하고 G4 evidence validator가 실제 최종 입력의 누락/stale/unknown을 거절하는지 확인한다.

## 범위 밖과 중단 조건

필수 gate나 acceptance가 실패/미확인인데 done_verified로 닫지 않는다. 실제로 실행하지 않은 외부 조합은 통과로 기재하지 않는다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 동작 확대는 범위 밖이다. Gate item은 이 ticket 또는 전이적 선행 산출물만 사용한다. 후속 통합의 책임을 초기 통과 조건으로 요구하지 않는다.

## 산출물 인계

귀속 가능한 candidate/output bundle, 변경 경로, 수행한 check와 미실행 이유, 실패/unknown, 소비할 계약·지원 조합을 Root에 전달한다. PLAN/state/approval은 Root만 수정한다. Ticket 상태만으로 acceptance 완료를 표시하지 않는다.
