## 제공할 동작

전체 candidate에서 C-AC-01~34의 사용자 행동과 G1~G4 근거를 연결해 최종 통합한다. 일반 terminal, 외부 tmux/herdr 및 실제 Bash/sh 조합의 호환 결과를 기록한다. C-D49의 turn 중단 요청/확인·불명 결과, 일시정지 중 자동 모델 작업 보류, 명시적 재개 대조, worker 수정 필요 보고 후 지시 종료를 포함한다. C-D50..52의 관리된 환경·control 대기·인수 중 불명과 foreground 수동 입력도 최종 I-SHELL/I-FAULT에서 검증한다.

### C-D72 결정 (p2.7u)

- 지원 shell은 Bash 우선·sh fallback뿐이다. 기본/login shell이 zsh인 경우의 안내·실제 zsh 검증은 C-AC-20 범위에서 뺀다([C-D72](../DECISIONS.md#C-D72)).
- 최종 OMP 버전은 18.8.0이다. 18.2.10 고정 G1·G3 probe는 이전 기록으로 두고 영향 대조표로 연결하며, 고정 probe는 실행 버전 기록 방식으로 바꾼다.
- worker 직접 요청: 열린 Task 범위 안 → 그 Task로 수행, Task 없는 작은 요청 → 제한 없음, 범위 확대 → manager 보고.
- 원본 OMP 승인 창이 제품 구성에서 나타나지 않으면 근거를 붙여 "해당 없음".

## 검증

모든 runtime 항목은 CW-17 제품 진입점으로 시작한 backend와 CW-06 UI에서 실행한다. 실제 두 OMP·persistent host shell에서 목표→승인→worktree/run→60초 점검→완료·실패 복구, worker 직접 요청의 기존 범위·새 작은 명세·범위 확대 경계, 세션 설정 변경 후 현재 run/재시도 유지, 수동 제어, detach, 저장/모델 장애를 시험한다. C-AC-19/20은 일반 terminal/tmux/herdr 각각에서 backend를 유지한 UI detach/재attach를 포함해 조작하고, Bash·실제 sh matrix를 조작하며 기본/login shell이 zsh인 경우, Bash/sh가 둘 다 없는 경우의 안내를 검증한다. 누락된 service/capability는 pending으로 남긴다. test_designer와 fresh reviewer 및 최종 checks를 실행한다. C-D50..52의 정상 handoff·control 대기·환경 전환·전송 중 인수/foreground 수동 입력을 최종 UI/backend에서 확인한다. I-FAULT의 재부팅은 C-D56 격리 VM에서 실제 guest 재부팅으로 확인하고 사용자 host는 재부팅하지 않는다. I-* 다섯 항목을 34개 C-AC 모두에 연결하고 G4 evidence validator가 실제 최종 입력의 누락/stale/unknown을 거절하는지 확인한다.

시작 전 UR-USABILITY 사용자 검토(C-D57)가 끝나 있어야 한다.

## 범위 밖과 중단 조건

필수 gate나 acceptance가 실패/미확인인데 done_verified로 닫지 않는다. 실제로 실행하지 않은 외부 조합은 통과로 기재하지 않는다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 동작 확대는 범위 밖이다. Gate item은 이 ticket 또는 전이적 선행 산출물만 사용한다. 후속 통합의 책임을 초기 통과 조건으로 요구하지 않는다.

## 산출물 인계

귀속 가능한 candidate/output bundle, 변경 경로, 수행한 check와 미실행 이유, 실패/unknown, 소비할 계약·지원 조합을 Root에 전달한다. PLAN/state/approval은 Root만 수정한다. Ticket 상태만으로 acceptance 완료를 표시하지 않는다.
