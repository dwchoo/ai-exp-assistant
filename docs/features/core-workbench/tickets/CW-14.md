# CW-14: 원문 로그 상한과 저장 장애

명세: [SPEC.md](../SPEC.md) s2.2. Scheduling·resource·scope의 원본: [PLAN.json](../PLAN.json) CW-14 항목. Live 상태와 작업 배정은 Root의 별도 workflow state에서 관리한다.

## 제공할 동작

Run raw log 64 MiB·project raw log 512 MiB cap, 잘림·누락·마지막 관측 표시를 구현한다. TaskSpec/결과 요약과 실행용 worktree는 자동 삭제하지 않는다.

## 수락 기준

- C-AC-24: 명세/요약/worktree 보존·64/512 MiB raw log cap. 최종 I-FAULT에서 재확인.
- C-AC-28: metadata 장애 차단과 raw log 장애 관측. 최종 I-FAULT에서 재확인.

## 계약과 선행 산출물

- CW-07: 실시간 log 수집에 쓸 PTY/lifecycle stream이 통합·검증됨.
- CW-09: metadata write gate와 안정적인 run ID가 통합·검증됨.

CW-07 PTY byte/lifecycle과 CW-09 metadata write gate를 소비한다. Metadata 실패는 새 자동 실행 보류, raw log 실패/상한은 실행·화면·가능한 관측 유지다. 실험 산출 파일은 cap 밖이다.

계획 write scope: `src/workbench/storage/log_*/**`, `tests/storage/**`. 실제 dispatch 전에 Root가 current base·소유권·resource claim을 다시 확인한다.

## 검증

한도 직전/정확히 도달/초과, 두 cap 중 먼저 도달, raw log 쓰기 실패와 metadata 쓰기 실패를 분리해 시험한다. 실험이 계속되고 누락 구간이 표시되는지 확인한다. 독립 test_designer/reviewer가 byte accounting과 삭제 금지 경계를 점검한다.

공통 검증: worker quick check → 독립 test_designer 평가/필요 테스트 → 동결 후보 fresh reviewer → 필요한 수정·delta review → Root 통합 및 SPEC의 최종 check. 명령·cwd·candidate·환경·결과를 기록한다.

## 범위 밖과 중단 조건

상한으로 실행을 종료하거나 손실된 log를 복원 완료로 표시하거나 metadata 오류를 무시하고 새 자동 run을 시작하면 중단한다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 제품 동작 확대는 이 ticket의 범위가 아니다.

## 산출물 인계

변경 경로와 근거를 특정한 candidate/output bundle, 실제 수행한 check와 미실행 사유, 실패·미확인 gate/acceptance, 다음 ticket이 소비할 계약 변경점을 Root에게 전달한다. Ticket 작성자가 PLAN/state/approval을 직접 바꾸지 않는다.
