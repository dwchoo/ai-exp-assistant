# CW-13: Manager 복구·종료·완료 판단

명세: [SPEC.md](../SPEC.md) s2.2. Scheduling·resource·scope의 원본: [PLAN.json](../PLAN.json) CW-13 항목. Live 상태와 작업 배정은 Root의 별도 workflow state에서 관리한다.

## 제공할 동작

Manager가 worker 근거와 승인된 완료 조건을 대조해 완료 또는 추가 조사/복구를 결정한다. 실패 복구 재시도 3회, 종료 확인 뒤 변경·재실행, 권한·대상 확인 후 강제 종료를 집행한다.

## 수락 기준

- C-AC-04: worker 근거를 완료 조건과 대조한 manager 보고. 최종 I-FLOW에서 재확인.
- C-AC-07: 실패 복구 3회·설정 변경 뒤 사용 횟수 유지·추가 자동 실행 금지·시간 상한 없음. 최종 I-POLICY에서 재확인.
- C-AC-10: 실행 종료 확인 뒤 소스·설정 수정. 최종 I-POLICY에서 재확인.
- C-AC-13: manager의 근거·권한·재시도 판단. 최종 I-POLICY에서 재확인.
- C-AC-31: 새 revision은 다음 run에 적용하고 현재 실행 적용 지시는 종료 확인 뒤 재실행하며 즉시 제한은 우선. 최종 I-POLICY에서 재확인.
- C-AC-34: 허용된 확인 대상만 강제 종료·실제 종료 검증. 최종 I-POLICY에서 재확인.

## 계약과 선행 산출물

- CW-10: Task→run/worktree 흐름과 불변 run 근거가 통합·검증됨.
- CW-11: worker 관측과 조사 보고가 통합·검증됨.
- CW-12: 실행 결정을 막는 일시정지·취소 guard가 통합·검증됨.

CW-10의 run/worktree, CW-11의 조사 근거, CW-12의 pause/취소 경계를 소비한다. 최초 실행·정상 개선과 복구 재시도를 구분하고 commit/revision·세션 공통 설정 변경으로 count를 초기화하지 않는다. 세션 설정 변경은 다음 판단부터 적용하고 현재 run을 종료하지 않는다. Terminal 입력 owner를 우회하지 않는다.

계획 write scope: `src/workbench/policy/recovery_*/**`, `tests/policy/recovery_*/**`. 실제 dispatch 전에 Root가 current base·소유권·resource claim을 다시 확인한다.

## 검증

실행 중 새 명세의 다음 run 적용과 현재 실행 적용 지시의 중단·종료 확인·재실행, 즉시 권한 철회, Exit 0이나 부족한 결과만으로 완료되지 않는 사례를 확인한다. 세션 설정 변경 후 다음 판단에 새 설정 적용·현재 run 유지·이미 사용한 복구 횟수 보존, 복구 1~3회와 네 번째 차단, 시간 상한 없는 정상 실행, 중단 요청 후 미종료, 강제 종료 허용/미허용·대상 불명, 종료 뒤에만 코드 수정/재실행을 확인한다. 독립 test_designer/reviewer가 결정 근거와 stop 범위를 점검한다.

공통 검증: worker quick check → 독립 test_designer 평가/필요 테스트 → 동결 후보 fresh reviewer → 필요한 수정·delta review → Root 통합 및 SPEC의 최종 check. 명령·cwd·candidate·환경·결과를 기록한다.

## 범위 밖과 중단 조건

실제 종료·대상·권한이 불명확하면 수정/재실행/강제 종료를 보류하고 확인을 요청한다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 제품 동작 확대는 이 ticket의 범위가 아니다.

## 산출물 인계

변경 경로와 근거를 특정한 candidate/output bundle, 실제 수행한 check와 미실행 사유, 실패·미확인 gate/acceptance, 다음 ticket이 소비할 계약 변경점을 Root에게 전달한다. Ticket 작성자가 PLAN/state/approval을 직접 바꾸지 않는다.
