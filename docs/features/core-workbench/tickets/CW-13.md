# CW-13: Manager 복구·종료·완료 판단

명세: [SPEC.md](../SPEC.md) s2.4, 입력 [BRIEF r1.11](../BRIEF.md). 최초 구현 승인과 C-D53 정책 개정은 현재 run의 승인 기록을 따른다.
Scheduling·resource·write scope의 원본: [PLAN.json](../PLAN.json) `CW-13`. Live 상태/배정은 Root workflow record에서 관리한다.

## 제공할 동작

Manager가 worker의 로그·결과 파일 기반 1차 판단과 승인된 완료 조건을 대조해 성공·실패 또는 추가 조사를 2차 확인한다. 실패 복구 재시도 3회, 종료 확인 뒤 승인 범위 안의 수정·새 worker 지시·재실행, 해결 불가 보고, 권한·대상 확인 후 강제 종료를 집행한다.

## 수락 기준

- C-AC-04: worker 1차 판단의 출처·근거·미확인을 승인된 완료 조건과 대조한 manager 2차 확인·추가 조사·보고. `P-C-AC-04`와 최종 I-FLOW로 확인.
- C-AC-07: 종료 확인 뒤 승인 범위 안의 수정·새 worker 지시·재실행, 실패 복구 3회·설정 변경 뒤 사용 횟수 유지·해결 불가/한도 뒤 자동 중단·근거 보고·시간 상한 없음. `P-C-AC-07`와 최종 I-POLICY로 확인.
- C-AC-10: 실행 종료 확인 뒤 소스·설정 수정. `P-C-AC-10`와 최종 I-POLICY로 확인.
- C-AC-13: manager의 근거·권한·재시도 판단. `P-C-AC-13`와 최종 I-POLICY로 확인.
- C-AC-31: 새 revision은 다음 run에 적용하고 현재 실행 적용 지시는 종료 확인 뒤 재실행하며 즉시 제한은 우선. `P-C-AC-31`와 최종 I-POLICY로 확인.
- C-AC-34: 허용된 확인 대상만 강제 종료·실제 종료 검증. `P-C-AC-34`와 최종 I-POLICY로 확인.

## 계약과 선행 산출물

CW-10의 run/worktree, CW-11의 조사 근거, CW-12의 pause/취소 경계를 소비한다. 최초 실행·정상 개선과 복구 재시도를 구분하고 commit/revision·세션 공통 설정 변경으로 count를 초기화하지 않는다. 세션 설정 변경은 다음 판단부터 적용하고 현재 run을 종료하지 않는다. Terminal 입력 owner를 우회하지 않는다.

선행 산출물·통합 경계는 PLAN의 이 ticket 및 `dependency_artifacts`를 따른다.

- CW-10: Task→run/worktree 흐름과 불변 run 근거가 통합·검증됨.
- CW-11: worker 관측과 조사 보고가 통합·검증됨.
- CW-12: 실행 결정을 막는 일시정지·취소 guard가 통합·검증됨.

계획 write scope: `src/workbench/policy/recovery_*/**`, `tests/policy/recovery_*/**`. 실제 dispatch 전에 Root가 current base·mutation lease·resource claim을 재확인한다.

## 검증

정상 종료+성공 로그, 오류 종료+실패 로그, exit 0이지만 승인된 실험 기준 실패, 로그 부족으로 판단 보류, 종료 여부 unknown을 manager가 worker의 출처·근거와 대조해 2차 확인하는지 검증한다. 근거 부족이면 추가 조사를 지시하고, unknown일 때 완료·수정·재실행으로 건너뛰지 않는다. 실행 중 새 명세의 다음 run 적용과 현재 실행 적용 지시의 중단·종료 확인·재실행, 즉시 권한 철회를 확인한다. 세션 설정 변경 후 다음 판단에 새 설정 적용·현재 run 유지·이미 사용한 복구 횟수 보존, 승인 범위 안의 수정→새 worker 지시→재실행 1~3회와 네 번째 차단, 해결 불가·범위 밖·한도 도달 후 자동 중단 및 원인·로그/결과·시도·남은 문제 보고, 시간 상한 없는 정상 실행, 중단 요청 후 미종료, 강제 종료 허용/미허용·대상 불명, 종료 뒤에만 코드 수정/재실행을 확인한다. 독립 test_designer/reviewer가 결정 근거와 stop 범위를 점검한다.

소유 check의 기준은 `PLAN.gate_items`다. 아래는 해당 항목의 요약이며 supplier/evidence의 원본은 PLAN이다.

## 범위 밖과 중단 조건

실제 종료·대상·권한이 불명확하면 수정/재실행/강제 종료를 보류하고 확인을 요청한다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 동작 확대는 범위 밖이다. Gate item은 이 ticket 또는 전이적 선행 산출물만 사용한다. 후속 통합의 책임을 초기 통과 조건으로 요구하지 않는다.

## 산출물 인계

귀속 가능한 candidate/output bundle, 변경 경로, 수행한 check와 미실행 이유, 실패/unknown, 소비할 계약·지원 조합을 Root에 전달한다. PLAN/state/approval은 Root만 수정한다. Ticket 상태만으로 acceptance 완료를 표시하지 않는다.
