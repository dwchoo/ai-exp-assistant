# CW-08: Task 연계 두 역할 mailbox

명세: [SPEC.md](../SPEC.md) s2.3, 입력 [BRIEF r1.10](../BRIEF.md). 현재 묶음의 승인 기록은 [구현 승인](../../../../.workflow/core-workbench/runs/implement-p2.3-20260924/approval.json)이다.
Scheduling·resource·write scope의 원본: [PLAN.json](../PLAN.json) `CW-08`. Live 상태/배정은 Root workflow record에서 관리한다.

## 제공할 동작

Manager와 worker의 task/question/answer/report를 영속 Task/revision/run에 연결하고 두 OMP에 비침범 전달한다. 동일 `message_id`의 중복 처리를 막고 접수·주입 시도·API 호출 복귀·OMP 처리 관측·실제 답변·업무 완료를 구분한다.

## 수락 기준

- C-AC-02: Task 연계 task/question/answer/report 왕복과 동일 메시지 중복 방지. `P-C-AC-02`와 최종 I-FLOW로 확인.

## 계약과 선행 산출물

CW-05의 G3 공개 extension/role/session contract와 CW-09의 영속 기록을 소비한다. 주입 직전 pending·approval·composer·session generation 확인과 안정된 `message_id` dedupe를 지킨다. 전달 시도와 논리 메시지를 구분하고 불명 수락은 자동 replay하지 않는다. TUI에서 method 복귀만으로 전달 완료를 저장하지 않는다. 영속 delivery attempt에 관측 근거와 unknown을 보존하고 새 process/session에 이전 요청을 자동 재주입하지 않는다.

선행 산출물·통합 경계는 PLAN의 이 ticket 및 `dependency_artifacts`를 따른다.

- CW-05: G4 protocol과 G3 공개 OMP 전달 경로가 통합·검증됨.
- CW-09: 영속 Task/revision/run·논리 메시지/전달 상태 기록과 metadata write gate가 통합·검증됨.

계획 write scope: `src/workbench/ipc/**`, `omp_bridge/**`, `tests/bridge/**`. 실제 dispatch 전에 Root가 current base·mutation lease·resource claim을 재확인한다.

## 검증

두 실제 OMP TUI에서 durable Task/revision/run 연계 네 종류 메시지·reply를 전달한다. API method 복귀, 해당 ID의 OMP 처리 관측, 업무 결과를 기록에서 구분한다. Composer/approval/busy·session 변경·ACK 유실·전송 후 비동기 오류에서 false delivery success와 automatic replay가 없어야 한다. CW-09 store에 남긴 불명 attempt를 재로딩해도 새 session에 자동 재주입하지 않는다. 살아 있는 연결의 중복 방지와 process 재시작 복구 통합(CW-15)을 구분한다.

소유 check의 기준은 `PLAN.gate_items`다. 아래는 해당 항목의 요약이며 supplier/evidence의 원본은 PLAN이다.

| Item | 필요 근거 | 관측 |
|---|---|---|
| P-C-AC-02 | runtime | Task 연계 task/question/answer/report 왕복과 동일 메시지 중복 방지 |

Worker quick check → 독립 `test_designer` 평가/필요 테스트 → 필수 실패가 해결된 후보 동결 → fresh `reviewer` → 필요한 delta 검증 → Root 통합. 기존 review는 유효 범위와 함께 재사용한다. 각 명령·cwd·candidate·요구 digest·환경·exit code·결과·unknown을 기록한다. Runtime probe는 PTY/pipe drain과 bounded cleanup/잔존 확인을 포함한다.

## 범위 밖과 중단 조건

공개 API의 실제 의미가 G3 contract와 다르거나 사용자 입력을 침범하면 전달을 보류하고 contract 재검토를 요청한다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 동작 확대는 범위 밖이다. Gate item은 이 ticket 또는 전이적 선행 산출물만 사용한다. 후속 통합의 책임을 초기 통과 조건으로 요구하지 않는다.

## 산출물 인계

귀속 가능한 candidate/output bundle, 변경 경로, 수행한 check와 미실행 이유, 실패/unknown, 소비할 계약·지원 조합을 Root에 전달한다. PLAN/state/approval은 Root만 수정한다. Ticket 상태만으로 acceptance 완료를 표시하지 않는다.
