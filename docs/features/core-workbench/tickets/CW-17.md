# CW-17: Production backend 수명과 UI 연결 계약

명세: [SPEC.md](../SPEC.md) s2.7 "Production 조합", 입력 [BRIEF r1.13](../BRIEF.md). [C-D56](../DECISIONS.md#C-D56)에서 승인한 후속 계획 변경이다.
Scheduling·resource·write scope의 원본: [PLAN.json](../PLAN.json) `CW-17`. Live 상태/배정은 Root workflow record에서 관리한다.

## 제공할 동작

사용자가 실행할 수 있는 단일 제품 진입점을 제공한다. 진입점은 UI와 수명이 분리된 backend process를 시작하거나 이미 실행 중인 backend에 연결한다. Backend는 manager OMP·worker OMP·persistent host shell의 세 PTY와 bridge·저장소를 소유한다. UI를 닫아도 backend와 세 PTY는 유지되고, 다시 연결하면 같은 backend·같은 process identity에 attach한다. 새 run은 시작하지 않는다.

- 진입점: `python -m workbench`와 `[project.scripts]`에 시작·attach·상태 조회 동작을 둔다. 하위 명령 이름은 구현에서 정한다.
- Backend process: frontend와 다른 session(`setsid`)에서 실행한다. 한 data dir에는 backend 인스턴스가 하나만 뜨도록 lock을 건다. 이미 실행 중이면 새로 시작하지 않고 attach한다.
- Data dir: CLI 인자·환경 변수·XDG state 기본값 순으로 결정한다. 권한은 0700이다. `TaskRepository`·`RawLogStore`·`PauseJournal`·`LifecycleJournal`·workflow artifacts를 한 data dir 아래에 둔다.
- OMP 실행: test 전용 `start_omp` 패턴을 production launcher로 옮긴다. `omp_bridge/g3/bridge.ts` extension과 role·token·generation을 주입하고 `ProcessRef`를 기록한다. Credential은 저장하거나 복사하지 않으며, 기존 OMP 설정을 그대로 사용한다.
- Host shell: 기존 `PersistentShell`을 backend가 소유한다. 시작 전에 Bash→sh 선택과 둘 다 없을 때의 안내를 진입점에서 표시한다.
- Backend↔UI 계약: 새 `contracts/ui_v1`을 UDS 위의 versioned framed 계약으로 둔다. 다룰 메시지는 attach·detach·snapshot, pane별 `DisplayChunk` stream, input·paste·resize, focus와 입력 owner, 인수 요청·확인·handoff, 자동화 상태, 전체 종료 요청·확인, `confirm_boot`이다. 기존 `contracts/v1`과 `ports_v2`는 바꾸지 않고 재사용한다. Socket 권한은 0600이다.
- 최소 attach client: 계약 검증과 CW-06 이전 시험을 위한 최소 client다. 제품 UI는 CW-06이 소유한다.

## 수락 기준

이 ticket은 아래 C-AC의 backend·process 수명 부분만 local item으로 공급한다. 사용자 행동 전체의 최종 판정은 소유 ticket과 CW-16이다.

- C-AC-15/18: UI를 detach하고 60초 넘게 기다린 뒤 다시 attach해도, 같은 backend PID·두 OMP·부모 shell identity가 유지된다. 입력 owner·control mode도 보존되고 새 run이나 중복 전송은 없다. `L-CW17-DETACH`로 확인한다.
- C-AC-20: 실제 Bash와 sh에서 진입점이 전용 persistent shell을 선택한다. 둘 다 없으면 시작 요건을 안내하고 backend를 시작하지 않는다. `L-CW17-START`로 확인한다.
- C-AC-19: 계약 version 불일치를 거절한다. 2 MiB 초과이거나 queue 공간이 부족한 paste는 일부만 보내지 않고 전체 거절하며 이유를 전달한다. 연결이 끊겨도 backend는 유지된다. `L-CW17-CONTRACT`로 확인한다.

## 계약과 선행 산출물

선행 산출물·통합 경계는 PLAN의 이 ticket 및 `dependency_artifacts`를 따른다.

- CW-05: v1 envelope·`DisplayChunk`·`PaneId`, G4 수명 분리 판별 근거(`tests/gates/g4_lifetime/live_detach_probe.py`)
- CW-07: production `PersistentShell`과 Bash/sh 선택
- CW-08: `G3BridgeServer`·`TaskMailbox`와 role별 bridge 전달
- CW-09: `TaskRepository`와 metadata write gate

`ui_v1`은 새 versioned 계약이다. 기존 v1/ports_v2 caller 계약을 바꾸어야 하면 구현하지 않고 Root에 계획 변경으로 보고한다. G4 probe의 one-shot JSON socket은 출발점일 뿐이며 계약으로 승격하지 않는다.

계획 write scope: `src/workbench/backend/**`, `src/workbench/contracts/ui_v1.py`, `src/workbench/__main__.py`, `pyproject.toml`(`[project.scripts]`만), `tests/backend/**`, `tests/contracts/test_ui_v1*.py`. 실제 dispatch 전에 Root가 current base·mutation lease·resource claim을 재확인한다.

## 검증

소유 check의 기준은 `PLAN.gate_items`다.

| Item | 필요 근거 | 관측 |
|---|---|---|
| L-CW17-DETACH | runtime | 실제 진입점으로 backend를 시작하고 최소 client로 attach·detach한다. 60초 넘게 경과한 뒤 재attach해서 backend·두 OMP·부모 shell·supervisor identity와 입력 owner를 확인하고, 새 run·중복 전송이 없음을 확인한다. Plain PTY에서 실행한다. |
| L-CW17-START | runtime | 실제 Bash·dash, 기본 shell이 zsh인 경우, Bash/sh가 모두 없는 PATH에서 진입점의 선택과 안내를 확인한다. 이미 backend가 실행 중이면 새로 띄우지 않고 attach하는지 확인한다. |
| L-CW17-CONTRACT | fixture | `ui_v1` version·framing·크기 한도·2 MiB paste 전체 거절·client 단절 뒤 backend 유지를 확인한다. |

Worker quick check → 독립 `test_designer` 평가/필요 테스트 → 필수 실패가 해결된 후보 동결 → fresh `reviewer` → 필요한 delta 검증 → Root 통합. Runtime probe는 test가 소유한 data dir·UDS·process만 만들고, pidfd와 start-time으로 identity를 확인해 정리한다. 정상 경로에서 남은 process가 있으면 실패로 처리한다.

## 범위 밖과 중단 조건

다음은 이 ticket의 범위가 아니다.

- 세 영역 제품 UI: CW-06
- Task 흐름·60초 점검·pause 결합: CW-18
- 재시작·재부팅 복구: CW-19
- 내부 tmux 등 외부 multiplexer 사용

Backend를 systemd service나 부팅 시 자동 시작으로 등록하지 않는다. 재부팅 뒤에는 사용자가 진입점을 다시 실행하는 것이 전제다. 기존 v1/ports_v2 계약이나 CW-05 app entry 계약을 바꿔야 하면 멈추고 보고한다.

## 산출물 인계

귀속 가능한 candidate/output bundle, 변경 경로, 수행한 check와 미실행 이유, 실패/unknown, `ui_v1` 계약 문서와 CW-06·CW-18이 소비할 backend port 목록을 Root에 전달한다.
