## 제공할 동작

G2에서 검증된 부모 control 대기와 별도 실험 supervisor/subreaper를 production shell adapter로 연결한다. 인수 요청/확인, 전송된 명령 상태, 확인된 foreground 수동 입력, 직접 `wb-handoff` 뒤 부모 환경 보존·현재 권한·입력 반환 상태 재확인을 제공한다.

## 계약과 선행 산출물

CW-05가 고정한 G2 adapter port를 소비한다. 입력 owner·부모 shell mode·supervisor/experiment state·Task 성공은 별도다. 한 outstanding 자동 요청, PTY/control 분리, 입력 반환 장벽, unknown 보류, no replay를 유지한다. 사용자가 준비한 부모 PID/cwd/PATH/exported environment를 유지하고 app 환경을 주입하지 않는다. 실험은 별도 실행 단위이며 내부 cd·export를 부모에 자동 반영하지 않는다. 인수 확인에 실험 종료를 요구하지 않는다.

선행 산출물·통합 경계는 PLAN의 이 ticket 및 `dependency_artifacts`를 따른다.

## 검증

C-D55에 따라 conda 전용 점검과 환경 관리자별 activation/deactivation matrix는 제외한다. 일반 환경 상속·비전파와 정상 수동 준비·비호환 hook/trap 보류는 runtime으로 검증한다. 기존 venv 근거는 보존하되 관리자별 matrix를 확대하지 않는다.

실제 Bash와 sh에서 사용자가 준비한 부모 PID/cwd/PATH/exported environment가 유지되고 별도 실험 자식이 이를 상속하되 내부 변경을 부모에 남기지 않는지 확인한다. 수동 인수 직전 아직 미전송인 요청은 보내지 않고, 이미 전달된 명령은 실행/종료/불명을 그대로 표시한다. 실행 중 foreground stdin을 인수 후 직접 조작하며 실험 종료나 prompt 복귀를 인수 확인의 전제로 요구하지 않는다. 대상 불명일 때 입력을 보류한다. 수동 작업 뒤 직접 `wb-handoff`→부모 control 대기, supervisor 시작, 입력 반환 장벽, 비호환 hook/trap·수동 잔존 보류를 확인하고 인수/상태 대조 뒤 오래된 요청을 replay하지 않는다. 최초 승인+진행은 별도 AUTO ON을 요구하지 않으며 일시정지 중 handoff는 자동 재개가 아니다. Startup shell 선택·둘 다 없을 때 안내·app 환경 분리도 검증한다.

## 범위 밖과 중단 조건

Shell identity나 lifecycle 증거가 불명확할 때 자동 실행·종료를 추정해야 하면 중단한다. G2에서 검증하지 않은 shell은 지원 완료로 표시하지 않는다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 동작 확대는 범위 밖이다. Gate item은 이 ticket 또는 전이적 선행 산출물만 사용한다. 후속 통합의 책임을 초기 통과 조건으로 요구하지 않는다.

## 산출물 인계

귀속 가능한 candidate/output bundle, 변경 경로, 수행한 check와 미실행 이유, 실패/unknown, 소비할 계약·지원 조합을 Root에 전달한다. PLAN/state/approval은 Root만 수정한다. Ticket 상태만으로 acceptance 완료를 표시하지 않는다.
