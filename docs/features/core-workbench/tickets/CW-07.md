# CW-07: Persistent shell lifecycle과 수동 제어

명세: [SPEC.md](../SPEC.md) s2.2. Scheduling·resource·scope의 원본: [PLAN.json](../PLAN.json) CW-07 항목. Live 상태와 작업 배정은 Root의 별도 workflow state에서 관리한다.

## 제공할 동작

Host persistent Bash/sh에서 사용자 제어권 인수·반환, 같은 shell 자동 실행 eligibility, 명시적 lifecycle과 선택된 conda/venv 재사용을 구현한다.

## 수락 기준

- C-AC-08: 사용자 인수 시 자동 입력 중지·반환 후 재확인. 최종 I-SHELL에서 재확인.
- C-AC-26: cwd/환경 유지·입력 경합 보류·lifecycle 증거. 최종 I-SHELL에서 재확인.
- C-AC-32: 기존 conda/venv 재사용·app 환경 분리. 최종 I-SHELL에서 재확인.

## 계약과 선행 산출물

- CW-05: G4 control 계약과 G2에서 증명한 Bash/sh 경로가 통합·검증됨.

CW-05의 G2 shell adapter만 사용한다. 한 foreground run, 한 수락 요청, 숨은 queue 없음. UI focus·owner·pending 입력을 분리한다. Workbench Python 환경을 실험 shell에 주입하지 않는다.

계획 write scope: `src/workbench/terminal/shell_*/**`, `src/workbench/terminal/pty_*/**`, `tests/terminal/**`. 실제 dispatch 전에 Root가 current base·소유권·resource claim을 다시 확인한다.

## 검증

실제 Bash와 sh에서 cd/export/conda 또는 venv 이후 같은 shell의 worker command가 이어받는지 확인한다. 기본/login shell이 zsh인 경우 Bash 또는 sh를 별도로 시작하고 선택된 실행 파일·구현을 표시한다. 둘 다 없으면 시작 요건을 안내한다. 미제출 입력/REPL/suspend/owner/cwd mismatch는 거절·보류하고 반환 뒤 재확인한다. 독립 test_designer와 reviewer는 종료 확인/수동 입력 race를 점검한다.

공통 검증: worker quick check → 독립 test_designer 평가/필요 테스트 → 동결 후보 fresh reviewer → 필요한 수정·delta review → Root 통합 및 SPEC의 최종 check. 명령·cwd·candidate·환경·결과를 기록한다.

## 범위 밖과 중단 조건

Shell identity나 lifecycle 증거가 불명확할 때 자동 실행·종료를 추정해야 하면 중단한다. G2에서 검증하지 않은 shell은 지원 완료로 표시하지 않는다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 제품 동작 확대는 이 ticket의 범위가 아니다.

## 산출물 인계

변경 경로와 근거를 특정한 candidate/output bundle, 실제 수행한 check와 미실행 사유, 실패·미확인 gate/acceptance, 다음 ticket이 소비할 계약 변경점을 Root에게 전달한다. Ticket 작성자가 PLAN/state/approval을 직접 바꾸지 않는다.
