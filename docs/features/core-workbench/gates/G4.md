# G4: backend lifetime와 계약 경계

CW-05 feasibility candidate다. CW-09 store, CW-11 scheduler, CW-12 production
recovery, CW-15 제품 backend/frontend를 완성했다는 기록이 아니다.

## 구현 범위

`runtime/g4.py`는 단일 승인 fixture의 60초 timer, metadata fsync 장벽,
display frontend lease를 제공한다. frontend 연결 해제는 backend process를
종료하거나 experiment에 signal을 보내지 않는다. timer는 pause나 metadata
실패로 보류되어도 소비되며 자동 재시도하지 않는다. API 반환과 model 처리,
업무 성공은 서로 다른 관측이다.

`live_detach_probe.py`의 별도 Python backend가 실제 OMP 두 PTY, persistent
parent Bash PTY, 기존 split-PG supervisor를 소유한다. frontend는 probe의 private
UDS client다. 완성된 제품 TUI나 화면 재생 구현은 아니다. `user_owner`는
display lease의 user ownership이고 shell의 실제 `owner`/`owner_epoch`와
별도로 기록한다. 재접속으로 어느 쪽도 바꾸지 않는다.

OMP는 기존 G3 public extension을 사용한다. 임시 config/profile/session/cwd와
local scripted provider를 사용하며 상속된 `HERDR_*`를 제거한다. native tools를
비활성화한 bounded worker approval fixture다. 외부 모델 비용은 발생하지 않는다.
PTY는 backend의 drain thread, backend stdout/stderr는 frontend의 communicate
thread가 계속 소비한다. cleanup은 소유 process만 종료하고 PID residue를 확인한다.

기존 G2 common RUN에 `return_timeout`을 추가했다. 기존 caller의 5초 wire와
동작을 보존하고, non-default 값만 명시한다. 허용 범위는 `0 < seconds <= 300`이다.
이 fixture는 experiment `sleep 180`, deadline `240`을 사용한다. expiry는
UNKNOWN이며 input/control return을 성공으로 만들지 않는다. ptrace 차단과
privileged/setuid/file-capability exec는 기존 지원 보류 경계를 유지한다.

## 관측과 실행

```sh
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src:tests/gates/g3_omp \
  python tests/gates/g4_lifetime/live_detach_probe.py
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src:tests/gates/g3_omp \
  python tests/gates/g4_lifetime/live_detach_probe.py --paused
PATH=/path/to/venv/bin:$PATH sh tests/gates/harness/run-contracts.sh
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src \
  python -m unittest discover -s tests/gates/g4_lifetime -v
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src \
  python -m unittest discover -s tests/gates/g4_evidence -v
```

normal/paused는 각각 실제 62초 동안 frontend 없이 실행한다. 동일 backend,
OMP PID/session/generation, parent/supervisor/experiment, control mode,
shell/display ownership을 before/detach/reattach에서 대조한다. normal은 worker
provider request와 agent start/end가 각각 정확히 1이고 manager request는 0이어야
한다. paused는 실제 pause ACK 이후 timer 1회, delivery/provider/agent event 0회이며
host experiment 관측은 계속 증가해야 한다. 상세 PID, elapsed, ACK, drain byte와
cleanup 결과는 실행 JSON에 남긴다.

metadata fixture는 append/flush/file fsync와 최초 생성 시 directory fsync를
완료한 뒤 dispatch한다. injected failure는 새 dispatch만 보류하며 기존 실제
sleep process는 살아 있어야 한다. crash recovery, WAL, concurrent writer,
transaction rollback과 corruption 복구는 검증하지 않는다.

## Versioned ports와 aggregate

Python `contracts/ports_v2.py`와 TypeScript `contract/ports_v2.ts`는
ShellControl, Takeover, DeliveryObservation, AutomationState, ResumeEvidence를
`portVersion: 2`로 검증한다. 기존 v1 envelope는 변경하지 않았고 v1 delivery
adapter는 `local_received`만 부여한다. 알려지지 않은 version/field, takeover가
이미 전달된 작업을 취소한다는 주장은 거절한다. pause/cancel/metadata/approval 중
닫힌 조건이 있으면 dispatch를 보류하고 resume의 unknown은 허용하지 않는다.
이는 관측/승인 입력 계약이며 production recovery authorization 구현이 아니다.

`tests/gates/harness/aggregate.py`는 verifier가 별도로 고정한 context를 받는다.
M0와 G1–G4의 25개 소유 항목, candidate/requirements/approval/input hash,
evidence 파일 hash, 요구 수준, invocation, exit/result/unknown을 검사한다.
runtime 요구 항목에 fixture-only evidence를 넣으면 실패한다. record에서 trust
context를 만들어서는 안 된다. 원본 실행의 semantic 판정과 선행 evidence 재사용
승인은 Root의 책임이다. 다른 candidate의 records를 새 candidate로 덮어쓰지 않는다.
positive integrated-set test는 현재 integrated source bytes와 PLAN 소유 목록에
묶인 **validator fixture**이며 그 자체로 runtime gate 통과를 인증하지 않는다.

## Dependencies

G4 자체는 Python standard library를 사용한다. 기존 G1 screen/drain 경로에서
사용하는 pyte/wcwidth를 `pyproject.toml`에 실제 검증 버전으로 기록했다.
추가 scheduler/database/multiplexer dependency는 없다.

| --- | --- | --- | --- |
