## Potential Gotchas

- 최신 G3 single-task 실행의 exit 1은 당시 `provider_responses == 1` 조건 때문이었다. 코드의 새 조건으로는 재실행하지 않았다. G3.md는 이 차이를 설명한다.
- `tool_call`은 batch의 여러 도구가 실제 실행 전에 모두 준비될 수 있어 현재 pause gate는 준비된 B를 막지 못한다. `tool_execution_start`는 범용 pre-exec 차단 hook이 아니다.
- G2의 READY와 owner return은 사용자 입력 처리 완료 증거가 아니다. `wb-handoff`를 같은 shell에서 직접 실행한 fresh event와 남은 입력/job 상태를 결합해야 한다.
- G1 pyte는 임시 `/tmp/cw02-g1-venv`에만 설치됐다. 이번 재개에서 설치·OMP 업데이트·MCP Docker 실행은 하지 않았다.
- 총 child-run 사용량의 과거 append-only 기록은 ledger에서 완전하지 않다. 다음 agent dispatch 전 실제 history/예산을 대조하고, Oracle 4/4 한도는 유지한다.
