# CW-08: Task 연계 두 역할 mailbox

명세: [SPEC.md](../SPEC.md) s1. Scheduling·resource·scope의 원본: [PLAN.json](../PLAN.json) CW-08 항목. Live 상태와 작업 배정은 Root의 별도 workflow state에서 관리한다.

## 제공할 동작

Manager와 worker의 task/question/answer/report를 원래 Task/revision/run과 연결하고 두 OMP에 비침범 전달한다. 접수·주입 시도·API 수락·실제 답변·업무 완료를 구분한다.

## 수락 기준

- C-AC-02: Task 연계 task/question/answer/report 왕복. 최종 I-FLOW에서 재확인.

## 계약과 선행 산출물

- CW-05: G4 protocol과 G3 공개 OMP 전달 경로가 통합·검증됨.

CW-05의 G3 공개 extension/role/session contract를 소비한다. 주입 직전 pending·approval·composer·session generation 확인과 message ID dedupe를 지킨다. 불명 수락은 자동 replay하지 않는다.

계획 write scope: `src/workbench/ipc/**`, `omp_bridge/**`, `tests/bridge/**`. 실제 dispatch 전에 Root가 current base·소유권·resource claim을 다시 확인한다.

## 검증

두 실제 OMP에서 왕복과 직접 사용자 대화 우선, busy 대기, session 변경, 중복/timeout을 확인한다. 독립 test_designer는 실제 주입 경합을 테스트하고 reviewer는 extension 예외 격리를 검토한다.

공통 검증: worker quick check → 독립 test_designer 평가/필요 테스트 → 동결 후보 fresh reviewer → 필요한 수정·delta review → Root 통합 및 SPEC의 최종 check. 명령·cwd·candidate·환경·결과를 기록한다.

## 범위 밖과 중단 조건

공개 API의 실제 의미가 G3 contract와 다르거나 사용자 입력을 침범하면 전달을 보류하고 contract 재검토를 요청한다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 제품 동작 확대는 이 ticket의 범위가 아니다.

## 산출물 인계

변경 경로와 근거를 특정한 candidate/output bundle, 실제 수행한 check와 미실행 사유, 실패·미확인 gate/acceptance, 다음 ticket이 소비할 계약 변경점을 Root에게 전달한다. Ticket 작성자가 PLAN/state/approval을 직접 바꾸지 않는다.
