# CW-12: 자동화 일시정지와 진행 중 도구 작업

명세: [SPEC.md](../SPEC.md) s1. Scheduling·resource·scope의 원본: [PLAN.json](../PLAN.json) CW-12 항목. Live 상태와 작업 배정은 Root의 별도 workflow state에서 관리한다.

## 제공할 동작

자동화 일시정지를 요청하면 새 코드 변경·중단·run을 막고, 이미 시작한 현재 변경 도구 작업은 끝날 때까지 일시정지 중으로 표시한다. 관측·점검·읽기 조사·보고는 계속하며 모델 점검 중지는 별도로 제공한다. 승인 범위와 Task/revision/run·취소 기록을 유지한다.

## 수락 기준

- C-AC-25: 승인 범위·Task/revision/run·취소와 일시정지 중 관찰·보고 연결. 최종 I-POLICY에서 재확인.
- C-AC-30: 일시정지 중 관찰·보고 유지, 새 변경·실행 보류. 최종 I-POLICY에서 재확인.
- C-AC-33: 현재 도구 작업 완료 후 일시정지 상태 전환. 최종 I-POLICY에서 재확인.

## 계약과 선행 산출물

- CW-09: 영속 위임·취소·권한 상태가 통합·검증됨.
- CW-11: 일시정지 중에도 유지할 관측·점검 경로가 통합·검증됨.

CW-09의 승인/취소와 CW-11의 review 경계를 소비한다. 일시정지는 현재 run 종료나 도구 rollback을 뜻하지 않는다. 재개 전 현재 상태와 권한을 재확인한다.

계획 write scope: `src/workbench/policy/pause_*/**`, `tests/policy/pause_*/**`, `omp_bridge/policy_*/**`. 실제 dispatch 전에 Root가 current base·소유권·resource claim을 다시 확인한다.

## 검증

파일 쓰기 도구가 실행 중일 때 일시정지 요청, 다음 변경 도구 차단, 완료 후 일시정지 완료, 기존 run·review·읽기 전용 조사·보고 지속을 확인한다. Task/revision/run과 승인 범위·취소 기록이 유지되는지 확인하고 모델 점검 중지와 사용자 취소를 구분한다. 독립 test_designer/reviewer가 전이 경합을 평가한다.

공통 검증: worker quick check → 독립 test_designer 평가/필요 테스트 → 동결 후보 fresh reviewer → 필요한 수정·delta review → Root 통합 및 SPEC의 최종 check. 명령·cwd·candidate·환경·결과를 기록한다.

## 범위 밖과 중단 조건

이미 시작한 도구 작업을 완료 전에 취소/rollback 완료로 표시하거나 pause 중 새 변경이 시작되면 중단한다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 제품 동작 확대는 이 ticket의 범위가 아니다.

## 산출물 인계

변경 경로와 근거를 특정한 candidate/output bundle, 실제 수행한 check와 미실행 사유, 실패·미확인 gate/acceptance, 다음 ticket이 소비할 계약 변경점을 Root에게 전달한다. Ticket 작성자가 PLAN/state/approval을 직접 바꾸지 않는다.
