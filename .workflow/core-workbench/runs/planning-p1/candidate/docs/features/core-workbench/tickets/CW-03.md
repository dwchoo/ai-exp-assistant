# CW-03: G2 Bash/sh 같은 shell 실행

명세: [SPEC.md](../SPEC.md) s1. Scheduling·resource·scope의 원본: [PLAN.json](../PLAN.json) CW-03 항목. Live 상태와 작업 배정은 Root의 별도 workflow state에서 관리한다.

## 제공할 동작

G2: 실제 Bash 5.x와 현재 host의 sh 구현에서 Workbench 전용 persistent interactive shell 하나에 안전하게 자동 명령을 수락·실행·관측할 수 있는지 실증한다.

## 수락 기준

- G2: 위 제공 동작을 실제 조건에서 검증하고 재현 가능한 통과·실패·미확인 근거를 남긴다. 수락 ID는 직접 소유하지 않으며 후속 C-AC 검증의 선행 증거다.

## 계약과 선행 산출물

- CW-01: command ID·lifecycle·입력 owner의 임시 계약이 통합·검증됨.

CW-01 command ID/lifecycle/input-owner 계약을 소비한다. cwd/export/사용자 선택 환경을 보존하고 prompt·stdout marker·무출력으로 종료를 판정하지 않는다. Bash 부재 시 sh 시작과 실행 중 shell 고정은 별개다.

계획 write scope: `src/workbench/terminal/shell_*/**`, `tests/gates/g2_*/**`, `docs/features/core-workbench/gates/G2.md`. 실제 dispatch 전에 Root가 current base·소유권·resource claim을 다시 확인한다.

## 검증

실제 Bash와 /usr/bin/dash 경로에서 사용자 미제출 입력, REPL, suspend, nested/background, Ctrl+C, 종료 실패, cwd/환경 변경, Bash 부재 시 sh fallback을 확인한다. 애매한 경우 자동 입력 보류와 NEEDS_REVIEW를 관측한다. 독립 test_designer/reviewer가 race와 job-control 결과를 점검한다.

공통 검증: worker quick check → 독립 test_designer 평가/필요 테스트 → 동결 후보 fresh reviewer → 필요한 수정·delta review → Root 통합 및 SPEC의 최종 check. 명령·cwd·candidate·환경·결과를 기록한다.

## 범위 밖과 중단 조건

Bash 또는 sh의 필수 same-shell 입력 경계를 확정할 수 없으면 해당 경로를 통과로 쓰지 않는다. 새 shell 우회나 요구 축소가 필요하면 후속 ticket을 차단하고 재합의를 요청한다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 제품 동작 확대는 이 ticket의 범위가 아니다.

## 산출물 인계

변경 경로와 근거를 특정한 candidate/output bundle, 실제 수행한 check와 미실행 사유, 실패·미확인 gate/acceptance, 다음 ticket이 소비할 계약 변경점을 Root에게 전달한다. Ticket 작성자가 PLAN/state/approval을 직접 바꾸지 않는다.
