# CW-04: G3 독립 OMP bridge

명세: [SPEC.md](../SPEC.md) s1. Scheduling·resource·scope의 원본: [PLAN.json](../PLAN.json) CW-04 항목. Live 상태와 작업 배정은 Root의 별도 workflow state에서 관리한다.

## 제공할 동작

G3: 고정 OMP 버전의 두 독립 process에 공개 extension을 로드하고 task/question/answer/report의 session-bound 왕복을 실증한다.

## 수락 기준

- G3: 위 제공 동작을 실제 조건에서 검증하고 재현 가능한 통과·실패·미확인 근거를 남긴다. 수락 ID는 직접 소유하지 않으며 후속 C-AC 검증의 선행 증거다.

## 계약과 선행 산출물

- CW-01: role/message/session 계약과 게이트 harness가 통합·검증됨.

CW-01 versioned envelope를 소비한다. Python local bridge는 role·message ID·대상 session generation을 검증하고, extension은 주입 직전 idle/pending/approval/composer 상태를 확인한다. API 수락과 모델 처리 완료를 구분한다.

계획 write scope: `omp_bridge/**`, `src/workbench/ipc/bridge_*/**`, `tests/gates/g3_*/**`, `docs/features/core-workbench/gates/G3.md`. 실제 dispatch 전에 Root가 current base·소유권·resource claim을 다시 확인한다.

## 검증

두 OMP session의 일반 대화 중, busy/approval/미제출 composer 중, disconnect/reconnect와 중복 message ID에서 비침범·불명 결과를 확인한다. 실제 공개 API/버전과 extension 오류 격리를 기록한다. 독립 test_designer/reviewer가 race와 예외 경계를 평가한다.

공통 검증: worker quick check → 독립 test_designer 평가/필요 테스트 → 동결 후보 fresh reviewer → 필요한 수정·delta review → Root 통합 및 SPEC의 최종 check. 명령·cwd·candidate·환경·결과를 기록한다.

## 범위 밖과 중단 조건

Process-global hub를 두 process 간 delivery 증거로 쓰지 않는다. 공개 API로 요구 행동이 불가하면 G3 실패로 표시하고 mailbox production 작업을 막는다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 제품 동작 확대는 이 ticket의 범위가 아니다.

## 산출물 인계

변경 경로와 근거를 특정한 candidate/output bundle, 실제 수행한 check와 미실행 사유, 실패·미확인 gate/acceptance, 다음 ticket이 소비할 계약 변경점을 Root에게 전달한다. Ticket 작성자가 PLAN/state/approval을 직접 바꾸지 않는다.
