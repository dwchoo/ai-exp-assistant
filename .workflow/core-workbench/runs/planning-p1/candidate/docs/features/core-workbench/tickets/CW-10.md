# CW-10: 승인 Task에서 host run까지

명세: [SPEC.md](../SPEC.md) s1. Scheduling·resource·scope의 원본: [PLAN.json](../PLAN.json) CW-10 항목. Live 상태와 작업 배정은 Root의 별도 workflow state에서 관리한다.

## 제공할 동작

하나의 승인된 목표가 manager 준비/허용 local commit, worker의 실행용 worktree 준비, 같은 host shell 실행, worker 분석/보고로 이어지는 수직 흐름을 완성한다.

## 수락 기준

- C-AC-03: 실제 host shell 실행·출력과 worker 실행 의뢰. 최종 I-FLOW, I-SHELL에서 재확인.
- C-AC-05: manager 준비·worker 실행/분석·수정 요청 반환. 최종 I-FLOW에서 재확인.
- C-AC-09: commit 기준 실행용 worktree 가이드·준비 실패 처리. 최종 I-FLOW에서 재확인.
- C-AC-11: 위임 변경만 local commit·push/merge 분리. 최종 I-FLOW에서 재확인.

## 계약과 선행 산출물

- CW-07: 실제 shell 수락·lifecycle·수동 제어가 통합·검증됨.
- CW-08: 연결된 manager/worker 메시지 전달이 통합·검증됨.
- CW-09: 승인된 불변 TaskSpec/run과 metadata gate가 통합·검증됨.

CW-07 shell, CW-08 mailbox, CW-09 TaskSpec/run을 소비한다. Worktree는 일반 Git 도구를 따르는 운영 가이드이며 자동 관리 기능이 아니다. 사용자 변경 삭제·stash·개발 디렉터리 우회, push·merge를 자동 수행하지 않는다.

계획 write scope: `src/workbench/workflow/**`, `tests/workflow/**`, `docs/features/core-workbench/WORKTREE-GUIDE.md`. 실제 dispatch 전에 Root가 current base·소유권·resource claim을 다시 확인한다.

## 검증

실제 worktree를 기준 commit에서 준비해 cwd/commit/실험 환경을 기록하고 run 결과를 Task/revision과 연결한다. 준비 실패는 worker 원인 보고→manager 허용 범위 해결→불가 시 사용자 확인으로 간다. 독립 test_designer와 reviewer가 관련 없는 변경의 commit 포함·경로 혼동을 살핀다.

공통 검증: worker quick check → 독립 test_designer 평가/필요 테스트 → 동결 후보 fresh reviewer → 필요한 수정·delta review → Root 통합 및 SPEC의 최종 check. 명령·cwd·candidate·환경·결과를 기록한다.

## 범위 밖과 중단 조건

기준 commit이나 필요한 dirty/untracked·외부 입력이 불명확하면 실행을 보류한다. 일반 도구로 안전한 준비가 안 되면 개발 디렉터리 실행으로 우회하지 않는다.

Phase 2·내부 외부 multiplexer·무단 commit/push/merge·미승인 제품 동작 확대는 이 ticket의 범위가 아니다.

## 산출물 인계

변경 경로와 근거를 특정한 candidate/output bundle, 실제 수행한 check와 미실행 사유, 실패·미확인 gate/acceptance, 다음 ticket이 소비할 계약 변경점을 Root에게 전달한다. Ticket 작성자가 PLAN/state/approval을 직접 바꾸지 않는다.
