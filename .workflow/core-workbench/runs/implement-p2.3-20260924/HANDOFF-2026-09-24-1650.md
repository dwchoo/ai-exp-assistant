## Key Patterns Discovered

- 한 physical checkout의 writer는 한 명이다. 이번 run에서 동시 writer 격리 증거가 없어 모든 파일 변경을 직렬로 진행했다. Root만 ledger/state/approval을 수정한다.
- 승인된 문서 manifest와 동적인 gate evidence 파일의 최신 hash를 구분한다. G2/G3 기록은 승인 후 runtime 증거가 추가되어 manifest의 원본 hash와 달라질 수 있다.
- G2에서 PTY **master** flush는 foreground 입력 잔여분 제거 근거가 아니다. 실제 slave `TCIFLUSH`를 verified WAIT와 writer lock에서 수행하는 현재 후보가 Bash·dash 반례를 통과했다. 이것은 새 recovery 설계의 검증을 대신하지 않는다.
- Bash/dash의 SIGINT trap 안에서 hold를 풀면 원래 `eval`/`read`의 뒤쪽 코드가 실행될 수 있다. 수동 prompt 인수 ACK는 trap에서 발행하면 안 된다.
- G3의 공개 OMP TUI `getEditorText()`는 setup wizard를 건너뛴 실제 composer에서 확인해야 한다. OMP event는 message ID가 없어 단일 격리 요청·provider ID·전송 뒤 새 event·화면 marker로만 현재 요청과 연결했다.
